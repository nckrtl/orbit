---
title: "route"
description: "Create explicit hostnames for an App, point them at an AppInstance, change a hostname or publication intent, and remove Routes."
---

A Route is an App-owned hostname with one routing scope, a Node or an active Cluster, and at most one configured AppInstance target. Orbit generates a Route for every AppInstance it creates; the `route` family manages explicit Routes and the target and hostname of existing ones.

The [Routes reference](/reference/routes) owns the Route record, hostname generation, private projection, and the guards that refuse a change while an active AppInstance depends on it.

## Commands

| Command | Result |
| --- | --- |
| [`route:create`](#orbit-routecreate) | Create an explicit Route. |
| [`route:list`](#orbit-routelist) | List Routes. |
| [`route:show`](#orbit-routeshow) | Show one Route. |
| [`route:update`](#orbit-routeupdate) | Change the hostname or publication intent of an explicit Route. |
| [`route:target:set`](#orbit-routetargetset) | Set the single configured target. |
| [`route:target:unset`](#orbit-routetargetunset) | Clear the configured target. |
| [`route:destroy`](#orbit-routedestroy) | Remove a Route. |

Every command accepts `--json`. Route, App, AppInstance, Node, and Cluster arguments are numeric IDs. Human output prints the Route scope, target, status, and the Gateway request ID.

## orbit route:create

Create an explicit Route for an App. Give it a target, or give a targetless Route exactly one Node or Cluster scope.

```bash
orbit route:create <app> <hostname> [--publication=INTENT] [--target=ID | --node=ID | --cluster=ID]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `app` | yes | Numeric App ID that owns the Route. |
| `hostname` | yes | Route hostname. The Gateway normalizes it and refuses one that another Route owns. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--publication=INTENT` | `private` | `private` or `public`. The Gateway retains the intent even while the Route has no target. |
| `--target=ID` | none | Numeric AppInstance target. The Route scope derives from that AppInstance's Node or active Cluster. |
| `--node=ID` | none | Numeric Node scope for a targetless Route. |
| `--cluster=ID` | none | Numeric Cluster scope for a targetless Route. |

```bash
orbit route:create 4 shop.example.test --target=12
orbit route:create 4 preview.example.test --cluster=3
```

The CLI refuses `--target` together with a scope option (`route.scope_conflict`) and a targetless Route without exactly one scope (`route.scope_required`) before it sends a request. Creating the same Route again with identical App, hostname, intent, scope, and target returns the existing Route; a retry that changes one of those values fails with `route.retry_conflict`.

| Error code | Meaning |
| --- | --- |
| `route.hostname_invalid` | The hostname is not a valid normalized hostname. |
| `route.hostname_conflict` | Another Route owns the hostname. |
| `route.target_app_conflict` | The target AppInstance belongs to another App. |
| `route.target_inactive` | The target AppInstance is not active. |
| `route.target_conflict` | The target AppInstance already belongs to another Route. |
| `route.router_required` | The Cluster scope has no active Router. |

## orbit route:list

List every Route with its hostname, provenance (`generated` or `explicit`), publication intent, scope, target, and status.

```bash
orbit route:list [--json]
```

## orbit route:update

Change the hostname or the publication intent of an explicit Route. At least one option is required.

```bash
orbit route:update <route> [--hostname=HOSTNAME] [--publication=INTENT]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `route` | yes | Numeric Route ID. |

| Option | Meaning |
| --- | --- |
| `--hostname=HOSTNAME` | New explicit hostname. |
| `--publication=INTENT` | New publication intent, `private` or `public`. |

```bash
orbit route:update 9 --hostname=shop.example.com
```

A hostname change is the operation that replaces a production clone's preview hostname with its intended hostname. The Gateway accepts it when the Route is active, explicit, private, and has one target. It prepares the new certificate and Caddy sites, aligns a Laravel `APP_URL` or the rendered production `.env`, publishes private DNS as the cutover, and only then removes the old hostname state. The old hostname stays authoritative until the new one is ready.

<Note>
While a hostname change is unfinished, `route:show` exposes the requested hostname, checkpoint, `failed_step`, and `error_code`. Repeat the same request to resume; a different hostname returns a conflict without changing the in-progress operation.
</Note>

| Error code | Meaning |
| --- | --- |
| `route.update_required` | No option was given. |
| `route.hostname_immutable` | The Route is generated; only an explicit hostname can change. |
| `route.hostname_conflict` | Another Route owns the new hostname. |
| `route.reconciliation_required` | The Route is generated, has more than one target, or is active with a publication change that this operation does not reconcile. |
| `route.hostname_change_conflict` | A different hostname change is already in progress. |
| `instance.source_profile_missing` | The target has no recorded source profile; recover it through the same creation request with `--recover-source-profile`. |

## orbit route:target:set

Add or replace the one configured AppInstance target.

```bash
orbit route:target:set <route> <target>
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `route` | yes | Numeric Route ID. |
| `target` | yes | Numeric AppInstance ID. |

```bash
orbit route:target:set 9 12
```

Setting the existing target again returns the unchanged Route. The Gateway returns `route.target_conflict` and preserves both associations when the AppInstance belongs to another Route, or when replacement would detach an active AppInstance from its sole Route. An AppInstance from another App or an inactive AppInstance is rejected.

## orbit route:target:unset

Clear the configured target while keeping the Route, its hostname, scope, and publication intent.

```bash
orbit route:target:unset <route>
```

Clearing an already empty Route returns it unchanged. The Gateway returns `route.target_conflict` when clearing would leave an active AppInstance without a Route.

## orbit route:destroy

Delete a Route and only its Route-owned target rows.

```bash
orbit route:destroy <route>
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `route` | yes | Numeric Route ID. |

<Warning>
The Gateway refuses removal with `route.target_conflict` while an active AppInstance depends on the Route. Remove the AppInstance with `instance:destroy` instead; that removal clears the target and deletes a final-target Route as part of its own lifecycle.
</Warning>
