---
title: "realtime"
description: "Stream decoded realtime Gateway events as they arrive, or confirm realtime is not configured yet."
---

The Gateway can publish realtime events over a private WebSocket channel. `realtime:tail` connects to that channel, subscribes, and prints each decoded event as it arrives. Use it to watch fleet activity live, or to check whether realtime is reachable before relying on it from another tool.

## Before you start

`realtime:tail` and `orbit top` ask the active Gateway for its Reverb endpoint and app key, so a Gateway with an active `websocket` role needs no local configuration. To point at a different endpoint, store `realtime_url` and `realtime_key` on the active profile in `$ORBIT_HOME/config.json`, alongside `url` and `ca_path`, or set `ORBIT_REALTIME_URL` and `ORBIT_REALTIME_KEY` in the environment; `realtime:tail` uses those values when they are present and asks the Gateway only when they are not. `ORBIT_REALTIME_URL` looks like `wss://reverb.orbit`. When no source supplies both values, `realtime:tail` fails with `realtime.not_configured` and callers fall back to polling the affected commands instead.

Run `orbit realtime:show` to see what the active Gateway itself reports.

Realtime uses the active profile's selected CA file for both channel authorization and the WebSocket connection. A selected file stays required if it disappears or cannot be read; only a profile without a pin uses system trust. Channel authorization accepts a successful response from the selected Gateway directly and never follows redirects.

## Commands

| Command | Result |
| --- | --- |
| [`realtime:show`](#orbit-realtimeshow) | Show the Gateway's Reverb connection details. |
| [`realtime:tail`](#orbit-realtimetail) | Stream decoded realtime Gateway events as they arrive. |

Both commands accept `--json`.

## orbit realtime:show

Ask the active Gateway where its Reverb server is and which app key and channel a client uses to reach it.

```bash
orbit realtime:show [--json]
```

Human output shows a `Status` of `configured` or `not configured`, the Reverb `URL`, the `Channel` (always `orbit`), and the `Key` in full — the Reverb app key is public; the app secret never leaves the Gateway. `URL` and `Key` show `—` when no Node holds an active `websocket` role. JSON output returns `{ "url", "key", "channel", "request_id" }`, with `url` and `key` as `null` in the same case.

```bash
orbit realtime:show
orbit realtime:show --json
```

## orbit realtime:tail

Connect to the Gateway's realtime channel and print every event it carries until interrupted.

```bash
orbit realtime:tail [--types=FILTER,...] [--json]
```

| Option | Meaning |
| --- | --- |
| `--types=FILTER,...` | Comma-separated event type filters. Each filter is an exact type such as `process.status`, or a family prefix ending in `*` such as `node.*`. Omit the option to print every type. |
| `--json` | Print each event's full envelope as one JSON line instead of a formatted line. |

```bash
orbit realtime:tail
orbit realtime:tail --types=node.*,process.status
orbit realtime:tail --json
```

Human output prints one line per event as `<at>  <type>  <summary>`, where `<summary>` lists the event's data fields as space-separated `key=value` pairs. JSON output prints the event's `{type, id, at, data}` envelope, one complete JSON object per line. The command keeps streaming until interrupted; press Ctrl-C to stop it, which exits with the interrupted-signal status.

Event types follow `<family>.<verb>`, for example `node.created`, `instance.status`, `process.status`, `schedule.updated`, `database.created`, `firewall.updated`, `deploy_step.created`, and `deployment.log`.

`realtime:tail` needs an interactive terminal unless `--json` is set; a noninteractive invocation without `--json` fails with `input.noninteractive_required`. An invalid `--types` filter fails with `input.invalid`.

### Reconnection

When the socket drops, the command reconnects automatically with increasing backoff: 1, 2, 4, 8, 16, then 30 seconds between attempts. It keeps retrying rather than exiting, so a long-running `orbit realtime:tail` survives a Gateway restart or a brief network interruption.

Complete events already received before the peer disconnects are printed in order before reconnection. An incomplete final frame is discarded. Reconnecting starts a fresh stream; it does not replay earlier events or recover events missed while disconnected.
