The `orbit` command is a thin client. Every fleet command sends one HTTPS request to the active Gateway, and the Gateway does the work on the managed Nodes over SSH. The CLI never opens an SSH session to a Node itself.

Humans and coding agents use the same commands. Human output is readable in a terminal, and `--json` returns the same result as one structured document.

Each command is one Gateway endpoint. The [API reference](/api/overview) documents the same operations for clients that call the Gateway directly or through the [PHP SDK](/api/php-sdk).

## Command families

Commands are grouped by the record they manage. Each family has its own page with every command, argument, and option.

| Family | Manages |
| --- | --- |
| [`gateway`](/cli/gateway) | Local Gateway profiles and the trusted root certificate. |
| [`node`](/cli/node) | Machines in the fleet, their roles, access grants, and storage settings. |
| [`cluster`](/cli/cluster) | Optional groups of Nodes with one Router and one development TLD. |
| [`firewall`](/cli/firewall) | Named UFW rules on one Node. |
| [`tool`](/cli/tool) | Packages that Orbit installs on a Node through apt, Composer, Vite+, or Homebrew. |
| [`metrics`](/cli/metrics) | The Prometheus and Grafana role and its exporters. |
| [`dns`](/cli/dns) | A local development TLD resolver override on the operator machine. |
| [`app`](/cli/app) | Application records with one repository each. |
| [`instance`](/cli/instance) | App instances: development checkouts and production releases on one Node. |
| [`route`](/cli/route) | Hostnames that reach an App instance. |
| [`env`](/cli/env) | Stored App instance environment configuration and its `.env` projection. |
| [`database`](/cli/database) | The registry of mysql, pgsql, and sqlite connections. |
| [`process`](/cli/process) | systemd services and Docker containers owned by an App instance, a Node, or an App definition. |
| [`schedule`](/cli/schedule) | Recurring commands run by native systemd timers. |
| [`doctor`](/cli/doctor) | Verify-only drift checks across the fleet. |
| [`activity`](/cli/activity) | The Gateway's log of who ran what. |
| [`extension`](/cli/extension) | Optional local command extensions. |
| [`herdr`](/cli/herdr) | Named Herdr terminal sessions and observation grants. |
| [`workspace`](/cli/workspace) | Git worktrees owned by legacy Instances. |

## Select a Gateway

The CLI stores Gateway profiles in `$HOME/.orbit/config.json`. Set `ORBIT_HOME` to move that directory. Register a Gateway once, and every later command uses the active profile.

```bash
orbit gateway:add 10.70.0.1 --use
orbit gateway:status
```

`gateway:add` fetches the Gateway root certificate, pins it, and installs it in the operating-system trust store. The [gateway family](/cli/gateway) and the [Gateway trust reference](/reference/gateway-trust) describe the trust sequence and its recovery paths.

## Name the record you mean

Most commands take a numeric ID that `*:list` or `*:show` prints. A few families accept a name or domain as well.

| Selector | Accepted by |
| --- | --- |
| Numeric ID | Every family. Apps, App instances, Nodes, Clusters, Routes, Processes, and Tools all use their database ID. |
| Node ID or registered name | `--node` on `process`, `metrics`, `herdr`, `database`, and `node:role` and `node:settings` commands. |
| App instance ID or exact Route domain | `--instance` on `env` and `instance:database` commands. |
| Slug | `database` connections. |
| UUID | Installed Schedules. |
| Name with `--app` | App-owned process and Schedule definitions. |

## Confirm destructive changes

A command that deletes or detaches something asks for confirmation in an interactive terminal. Pass `--force` to skip the prompt. A non-interactive call, including every `--json` call, refuses a destructive change without `--force` and sends no request.

```bash
orbit instance:destroy 12
orbit cluster:destroy 3 --force --json
```

`--force` only skips the confirmation. It never waives a safety check on the Gateway. For example, `instance:destroy --force` may delete dirty source, but it still refuses a checkout whose path, owner, or repository does not match the record.

## Read machine-readable output

Every command accepts `--json`. Success returns one JSON document that includes the Gateway `request_id`. Failure returns one error envelope with a stable error code:

```json
{
  "error": {
    "code": "route.target_conflict",
    "message": "AppInstance 12 already belongs to Route 4.",
    "request_id": "9d6b1e5c-4a3f-4a1b-9f0e-6d2c3f5a7b81"
  }
}
```

Error codes are namespaced by family, such as `node.not_active`, `schedule.calendar_invalid`, or `env.operation_busy`. The reference pages list each family's codes and what the Gateway leaves in place after a refusal.

`instance:deploy` and `instance:rollback` stream newline-delimited JSON (NDJSON) instead of one document, because they report phases and application output while the Gateway is still working. The [instance family](/cli/instance#orbit-instancedeploy) describes that event stream.

## Follow a request through the Gateway

The Gateway records one Activity for every command it authorizes. Use the request ID from any result to find the matching attempt:

```bash
orbit activity:list --request-id=9d6b1e5c-4a3f-4a1b-9f0e-6d2c3f5a7b81
orbit activity:show 481
```

Activity records identify the operation, target, caller, and result. They never contain commands, environment values, credentials, or remote output.

## Exit status

A command exits with `0` when the Gateway accepted and completed the request. Any refusal, transport failure, or failed streamed operation exits nonzero. `orbit doctor` exits `1` when any check is unhealthy or unverifiable.

## Enable an extension

Some command families are hidden until you enable them on the operator machine. Extension state is local and changes nothing on the Gateway.

```bash
orbit extension:list
orbit extension:enable herdr
```

The [extension family](/cli/extension) lists the available extensions.

## Shell completion

The CLI is a Laravel Zero application, so `orbit completion bash` and `orbit completion zsh` print a completion script for your shell.

```bash
orbit completion zsh > ~/.zfunc/_orbit
```
