---
title: "extension"
description: "Enable or disable optional Gateway extensions consistently across Orbit clients."
---

An extension is an optional Gateway-owned product surface. Its one switch controls which CLI commands, MCP tools, API routes, and web navigation are available to every client. The Gateway stores the enabled set; the CLI does not keep a local copy. [ADR 0179](/decisions/0179-gate-all-extension-surfaces-with-one-gateway-switch) defines this model.

## Commands

| Command | Result |
| --- | --- |
| [`extension:list`](#orbit-extensionlist) | List known extensions and their Gateway state. |
| [`extension:enable`](#orbit-extensionenable) | Enable one extension for every client. |
| [`extension:disable`](#orbit-extensiondisable) | Disable one extension for every client. |

Each command accepts `--json`. Extension state comes from the selected Gateway. The CLI makes one bounded extension-state read during bootstrap with an explicit 2-second total deadline, shared across its single connection retry; this deadline is independent of the 900-second timeout used for operational reads. It does not loop or persist a local answer. That response supplies the enabled set for command listing, help, and dispatch for the process, and the Gateway checks direct operations again.

## Discovery and recovery

If no Gateway profile is active, the CA is not trusted, or the Gateway is unreachable, extension state is `unknown`, not `disabled`. `extension:list` reports `UNKNOWN` with the relevant `gateway.profile_missing`, `gateway.unreachable`, or certificate-trust guidance; JSON returns `enabled: null` and the state detail. A direct extension command fails with `extension.state_unknown` and does not make a change. The CLI does not hide this behind repeated retries. If the 2-second discovery deadline expires, the CLI uses this same unknown-state behavior.

The core `gateway:add`, `gateway:use`, `gateway:remove`, and `gateway:trust` commands and core help remain available without extension discovery, so an operator can establish, select, repair, or remove the active profile. After recovery, the next CLI process asks the Gateway again. Only a confirmed disabled extension is hidden and refused with `extension.disabled`.

## Available extensions

| Extension | Commands it reveals |
| --- | --- |
| `tasks` | The [`tasks`](/cli/tasks) family, including task group and subtask operations. |
| `proxycli` | The [`proxycli`](/cli/proxycli) family, including collector setup and quota operations. |

## orbit extension:list

List every known extension with its Gateway state.

```bash
orbit extension:list [--json]
```

Human output is one table with the columns EXTENSION and STATE. JSON output returns an `extensions` array with `extension` and `enabled` for each entry.

## orbit extension:enable

Enable one extension. Its commands, MCP tools, API operations, and web navigation become available to every client.

```bash
orbit extension:enable <extension> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `extension` | yes | Extension slug: `tasks` or `proxycli`. |

```bash
orbit extension:enable tasks
orbit extension:enable proxycli
```

An unknown slug fails with `extension.unknown`. Enabling an already enabled extension succeeds without changing state.

## orbit extension:disable

Disable one extension across the Gateway. Its CLI commands disappear from listings, its API operations refuse requests, MCP omits its tools, and web navigation hides its pages. Existing extension data is retained.

```bash
orbit extension:disable <extension> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `extension` | yes | Extension slug. |

```bash
orbit extension:disable tasks
```

A stale CLI invocation or API request for a disabled extension fails with `extension.disabled`; the API response uses HTTP 409. MCP reports the same code in its tool-error envelope rather than as an HTTP 409; see [MCP errors](/reference/mcp#tools). Disabling `proxycli` hides access but does not tear down its configured collector; use [`proxycli:teardown`](/cli/proxycli#orbit-proxycliteardown) to remove that fleet setup before disabling it when desired.
