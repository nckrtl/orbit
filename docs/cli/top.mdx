`orbit top` is one live screen. It loads every Node, App, App instance, Process, Schedule, Firewall rule, and Database connection once, then keeps that data current from realtime Gateway events or, when realtime is not available, by reloading on a fixed tick. Use it to watch the fleet, drill into one record, and run a small set of safe actions without leaving the screen.

## Commands

| Command | Result |
| --- | --- |
| [`top`](#orbit-top) | Show the fleet as a live screen. |

`top` does not accept `--json`: it is an interactive screen with no single final result to return.

## orbit top

```bash
orbit top [--tick=SECONDS]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--tick=SECONDS` | `10` | Seconds between reloads when realtime is not available. |

`orbit top` needs an interactive terminal.

## Sections and pages

The sidebar lists seven sections: Dashboard, Nodes, Apps, Instances, Processes, Schedules, and Databases. Each record family's section is its list; Enter or a click on a row opens that record's page. Pages stack, so Esc or the `‹ back` link returns one step at a time. Instances, Processes, and Schedules carry a Node and App filter bar.

- **Dashboard** shows a count per family (yellow when something in it needs attention), a compact CPU/memory/disk line per Node, and a "Needs attention" list gathering every row that is off across every family.
- **Nodes** lists registered Nodes. `+ create` opens a form with the same fields `node:add` accepts (name, host, SSH port, user, roles, TLD); submitting it sends the same `AddNodeRequest` the command sends. A Node's own page adds its instances, its Node-owned processes, and its firewall rules to its properties.
- **Apps**, **Instances**, **Processes**, **Schedules**, **Databases** list their family and open a record page with that family's properties and related panes (an Instance's processes, schedules, deploy steps, and deployments; a Database connection's tables and users).

## Keys and mouse

| Key | Effect |
| --- | --- |
| `↑` `↓` | Move the sidebar selection, or the selection within the focused pane. |
| `→` / `Enter` | Move from the sidebar into the page, or focus a hovered pane. |
| `←` / `Esc` | Move focus back out, or go back one page. |
| `1`-`7` | Jump straight to a section. |
| `c` | On the Nodes list, open the create-Node form. |
| `n` / `p` | On a list with a filter bar, cycle the Node or App filter. |
| `a` | Open the actions menu for the focused or selected row. |
| `q` | Leave `orbit top`. |

A click selects a row; clicking the already-selected row opens it. A right click opens the actions menu at the pointer. The mouse wheel scrolls the pane under the pointer. Resizing the terminal redraws the screen at its new size.

## Actions

The actions menu (`a` or a right click) lists what a record supports. Process start, stop, and restart; Schedule run and enable; Node doctor; Database connection destroy (with an inline confirmation); and Firewall rule removal (with an inline confirmation) run the same SDK request their matching command sends, and the row updates from the response.

A few actions have no request to run synchronously inside a screen that must keep rendering, or no request at all yet: App instance deploy and rollback stream for minutes; `node:ssh`, `instance:profile`, and `database:query` need an interactive terminal of their own. Choosing one of these prints the equivalent command in the footer and returns to the screen instead of running anything.

## Realtime and polling

At startup, `orbit top` asks the Gateway for its realtime endpoint. When the Gateway answers with a configured `url` and `key`, `orbit top` connects and applies each event (`node.created`, `process.status`, `schedule.updated`, and so on) to the row it names as it arrives. A `node.sample` event updates that Node's dashboard metrics line directly, even before a Gateway exposes a metrics endpoint to poll.

When realtime is not configured on the Gateway, `orbit top` falls back to the active profile's own `realtime_url`/`realtime_key`, or to `ORBIT_REALTIME_URL`/`ORBIT_REALTIME_KEY` (see [realtime](/cli/realtime)). When none of those resolve a socket, or the socket drops, `orbit top` reloads every list on the `--tick` interval instead. The header names the current mode: `live`, `reconnecting`, or `polling every Ns`.

## Panes not every Gateway can fill yet

Deployment history on an App instance's page, the users recorded on a Database connection, and a Node's CPU/memory/disk metrics (outside of a `node.sample` realtime event) depend on Gateway endpoints a parallel effort is still adding. Until a Gateway exposes them, those panes show "Not available on this Gateway yet." instead of a table; every other pane on the same page still renders normally.
