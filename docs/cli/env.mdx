The Gateway stores the environment configuration of every Instance as encrypted keys and values. The `env` family imports an existing `.env`, changes one stored value, and writes the complete stored configuration back into the Instance's `.env`.

[Instance environment variables](/reference/environment-variables) describes the file location, the limits, the placeholders, and the error codes.

## Commands

| Command | Result |
| --- | --- |
| [`env:import`](#orbit-envimport) | Import the Instance's `.env` into stored configuration. |
| [`env:update`](#orbit-envupdate) | Add or replace one stored value. |
| [`env:sync`](#orbit-envsync) | Replace the Instance's `.env` with the complete stored configuration. |

Every command takes `--instance=SELECTOR`: a positive Instance ID or the exact domain of its Route. The commands have no app selector. They act on the sole app of a single-app Project; on a Project with several apps they return `app.required`. A Route is required only to render a stored domain placeholder. Every command accepts `--json`. Output holds the Instance ID, the operation, whether something changed, the total stored key count, and the request ID. Values never appear. Import and update change stored configuration only; the file stays the same until you run `env:sync`.

## orbit env:import

Import the Instance's `.env` into stored configuration. The Gateway never reads `.env.example`.

```bash
orbit env:import --instance=SELECTOR [--replace] [--json]
```

| Option | Meaning |
| --- | --- |
| `--replace` | Replace stored keys that the file also holds. Stored keys that the file lacks stay. |

Without `--replace`, a file key that is already stored returns `env.import_conflict`, and nothing is stored. For a Laravel Instance, import stores `APP_URL` as `https://{{instance.domain}}`.

```bash
orbit env:import --instance=12
orbit env:import --instance=shop.example.test --replace
```

## orbit env:update

Add or replace one stored value.

```bash
orbit env:update --instance=SELECTOR --key=KEY --value=VALUE [--json]
```

| Option | Meaning |
| --- | --- |
| `--key=KEY` | 1 to 255 characters that start with a letter or underscore. |
| `--value=VALUE` | The exact string, at most 65,536 bytes. |

Quote the value for your shell, so Orbit receives the string you mean.

| Value | Write it as |
| --- | --- |
| Empty | `--value=''` |
| Text with spaces or shell characters | `--value='hello world $1'` |
| A placeholder | `--value='https://{{instance.domain}}'` |
| `false` or `0` | `--value=false` stores the string `false`. |

```bash
orbit env:update --instance=12 --key=MAIL_MAILER --value=log
orbit env:update --instance=12 --key=APP_URL --value='https://{{instance.domain}}'
```

`{{instance.domain}}` resolves to the Route domain, and `{{instance.environment}}` to `development` on `app-dev` or `production` on `app-prod`, when the Gateway renders the file. Any other placeholder returns `env.configuration_invalid` with the key and the rule.

## orbit env:sync

Replace the Instance's `.env` with the complete stored configuration. Keys and edits that exist only in the file disappear, so import them first when they must stay.

```bash
orbit env:sync --instance=SELECTOR [--json]
```

```bash
orbit env:sync --instance=12
```

<Note>
Synchronization changes only the file. It does not clear a framework cache or restart a Process. Run those steps afterwards when running code must see the new values.
</Note>

`env.sync_unconfirmed` means that the Gateway cannot confirm the write. Run the command again to check the file.
