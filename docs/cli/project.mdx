A Project records one Git repository and the defaults for running it. [Projects](/reference/projects) owns the fields, types, update lifecycle, and error codes. [Applications](/domains/applications) shows how a Project becomes an Instance.

## Commands

| Command | Result |
| --- | --- |
| [`project:create`](#orbit-projectcreate) | Create a Project from a slug, a type, and a repository URL. |
| [`project:list`](#orbit-projectlist) | List Projects. |
| [`project:show`](#orbit-projectshow) | Show one Project. |
| [`project:update`](#orbit-projectupdate) | Change a Project and reconcile its Instances. |
| [`project:destroy`](#orbit-projectdestroy) | Remove a Project. |
| [`project:dev-deploy-step:list`](#orbit-projectdev-deploy-steplist) | List development deploy steps. |
| [`project:dev-deploy-step:create`](#orbit-projectdev-deploy-stepcreate) | Record a development deploy step. |
| [`project:dev-deploy-step:update`](#orbit-projectdev-deploy-stepupdate) | Change a development deploy step. |
| [`project:dev-deploy-step:destroy`](#orbit-projectdev-deploy-stepdestroy) | Remove a development deploy step. |

Every command accepts `--json`. [`project:excluded-node`](/reference/development-node-exclusions) keeps a Project off selected `app-dev` Nodes.

## Project Documents

Use `project:document:<verb>` with a Project ID or slug. The [Project Documents command contract](/reference/project-documents#cli-contract) lists browsing, search, folder creation, file input/output, metadata changes, archive, restore, version history, and removal. `project:document-storage:show` and `project:document-storage:update` configure Gateway-owned storage without a Project selector.

Mutations require an observed `--expected-revision`; permanent removal also requires `--yes` without a terminal. JSON mode preserves the API envelope. Local validation uses `input.invalid` and exit 2. Local download integrity or filesystem failures use `project_documents.local_io_failed` and exit 1. On `project_documents.revision_conflict`, preserve the draft and reread metadata rather than retrying automatically.

```bash
orbit project:document:list acme
orbit project:document:create acme notes --kind=folder
orbit project:document:upload acme 12 --from=spec.pdf --expected-revision=3
orbit project:document:download acme 12 --output=downloaded-spec.pdf
```

## orbit project:create

```bash
orbit project:create <slug> <type> <repository> [options]
```

| Argument | Meaning |
| --- | --- |
| `slug` | Unique Project slug. |
| `type` | `monorepo`, `laravel-app`, `laravel-package`, or `node-package`. |
| `repository` | HTTPS or SSH Git URL. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--name=NAME` | the slug | Display name. |
| `--source-access=VALUE` | `github_app` | `github_app` or `gh_cli`. How Orbit reads a private `github.com` repository. See [Source access](/reference/projects#source-access). |
| `--default-branch=BRANCH` | the remote default | Stored default branch. The Gateway verifies that an explicit branch exists. |
| `--root=PATH` | `.` for `laravel-package` and `node-package`; `public` otherwise | Normalized repository-relative root that Instances inherit. `.` means the repository root. |
| `--task-check=COMMAND` | none | Command that task baselines and handoffs run in the workspace. See [Project check](/reference/tasks#project-check). |
| `--task-workspace-routed=true\|false` | true | Whether new task workspaces get a Route. See [Task workspace routing](/reference/projects#task-workspace-routing). |

```bash
orbit project:create acme laravel-app git@github.com:acme/site.git
orbit project:create support laravel-package git@github.com:acme/support.git
orbit project:create node-kit node-package git@github.com:acme/node-kit.git --task-check="vp run check"
orbit project:create leden laravel-app git@github.com:acme/leden.git --source-access=gh_cli
```

A retry with the same values returns the existing Project.

## orbit project:list

List every Project with its slug, type, repository, default branch, and root. JSON output also includes the source access.

```bash
orbit project:list [--json]
```

## orbit project:show

Show one Project with its source access, source defaults, task check, task workspace routing, and excluded Nodes. Human detail output labels the boolean `Task workspace routed`; JSON uses `task_workspace_routed`. Null `default_branch` or root values mean the source defaults are incomplete, and new Instance creation fails with `project.source_defaults_incomplete` until they exist. A null task check means tasks run no check command. Human output also lists the Project's Instances with ID, name, environment, Node, domain, and status. In a terminal, selecting an Instance opens `instance:show`.

```bash
orbit project:show <project> [--json]
```

## orbit project:update

Change a Project's type, source access, source defaults, task check, or task workspace routing. Omitted fields stay unchanged. The Gateway reconciles affected development sources, checkouts, Routes, inherited web roots, and runtimes before publishing the change. It does not start a production deployment. See [Update a Project](/reference/projects#update-a-project) for validation, rollback, and retry behavior.

```bash
orbit project:update <project> [--type=TYPE] [--slug=SLUG] [--repository=URL] [--source-access=VALUE] [--default-branch=BRANCH] [--root=PATH] [--task-check=COMMAND] [--clear-task-check] [--task-workspace-routed=true|false]
```

| Option | Meaning |
| --- | --- |
| `--type=TYPE` | New Project type. A change to `laravel-app` is refused while an active Instance has no Route. |
| `--slug=SLUG` | New Project slug. Generated development domains follow it; recorded paths stay unchanged. |
| `--repository=URL` | New Git access URL. The Gateway validates ownership before updating checkout origins. |
| `--default-branch=BRANCH` | New default branch for development sources that inherit it. |
| `--source-access=VALUE` | `github_app` or `gh_cli`. Applies at once after the Gateway reads the remote with the new value. |
| `--root=PATH` | New normalized repository-relative root for Instances without an override. Package types may use `.`. |
| `--task-check=COMMAND` | New command that task baselines and handoffs run. A type change does not change it. |
| `--clear-task-check` | Remove the task check so tasks run no check command. Combining it with `--task-check` fails with `project.task_check_conflict`. |
| `--task-workspace-routed=true\|false` | Change routing for future task workspaces. Invalid values return `project.task_workspace_routed_invalid` before a request. Existing workspaces keep their mode. |

## orbit project:destroy

Remove a Project that has no Instances and no Routes. Its definitions, setup steps, Node exclusions, and update records go with it. A Project with tasks cannot be removed: the request fails with HTTP 409 and `project.has_task_groups`. See [Remove a Project](/reference/projects#remove-a-project).

```bash
orbit project:destroy <project> [--yes] [--json]
```

The CLI shows the Project and asks for confirmation, with No selected. `--yes` confirms without a prompt and is required for JSON and noninteractive calls.

## orbit project:dev-deploy-step:list

List the Project's development deploy steps in stored order. Each entry shows its name, command, timeout, and whether it is required. JSON returns `steps` and `request_id`.

```bash
orbit project:dev-deploy-step:list --project=4 [--json]
```

## orbit project:dev-deploy-step:create

Record a named step without starting a deployment. Human step results show control characters as visible escapes and preserve literal text such as `<error>` tags; JSON preserves the stored command unchanged. [Development deploy steps](/reference/deployments#development-deploy-steps) owns the limits, placement rules, and required-versus-best-effort behavior.

```bash
orbit project:dev-deploy-step:create install --project=4 --command="composer install --no-interaction" [--timeout=300] [--required=true|false] [--before=NAME | --after=NAME] [--json]
```

| Option | Meaning |
| --- | --- |
| `--project=ID` | Required numeric Project ID. |
| `--command=COMMAND` | Required shell command for create; replacement command for update. |
| `--timeout=SECONDS` | Step timeout, default 300 on create. |
| `--required=true\|false` | Whether failure prevents activation. Defaults to true on create. |
| `--before=NAME` | Place before another step in this list. |
| `--after=NAME` | Place after another step in this list. Cannot be combined with `--before`. |

## orbit project:dev-deploy-step:update

Change a named step. Omitted fields keep their stored values. A required-only update is supported. JSON for create, update, and remove returns `name`, `command`, `timeout_seconds`, `required`, and `request_id`.

```bash
orbit project:dev-deploy-step:update cache --project=4 --required=false [--command=COMMAND] [--timeout=SECONDS] [--before=NAME | --after=NAME] [--json]
```

## orbit project:dev-deploy-step:destroy

Remove a named step. The remaining steps keep their order. `--yes` confirms without prompting and is required for JSON and noninteractive calls.

```bash
orbit project:dev-deploy-step:destroy cache --project=4 [--yes] [--json]
```
