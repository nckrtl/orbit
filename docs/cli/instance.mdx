An Instance is one copy of a Project on one Node. On an `app-dev` Node it owns a checkout or worktree. On an `app-prod` Node it owns a Unix user and a production home with releases. The [Project type](/reference/projects#project-types) decides whether it gets a Route.

[Applications](/domains/applications) walks through the lifecycle. [Production release layout](/reference/deployments), [Instance setup and teardown](/reference/instance-setup), [Instance cloning](/reference/instance-cloning), [Instance transfer](/reference/instance-transfer), [Instance removal](/reference/instance-removal), and [Database connections](/reference/database-connections) own the contracts behind these commands.

## orbit instance:create

Create a development Instance on a Node with the active `app-dev` role. A Node with the active `app-prod` role returns `instance.candidate_required`, including a repeat for an existing production Instance. Create a production Instance with [`instance:clone`](#orbit-instanceclone).

```bash
orbit instance:create <project> <node> <name> [options]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `project` | yes | Numeric Project ID. |
| `node` | yes | Numeric Node ID. |
| `name` | yes | Instance name. `default` is reserved for the Project's default development source. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--root=PATH` | the Project root | Relative web-root override for this Instance. |
| `--domain=HOST` | generated | Explicit Route domain for the development source. Without it, Orbit generates a domain from the active Cluster TLD, then the Node TLD. |
| `--branch=BRANCH` | see [branch selection](/domains/applications#create-a-development-instance) | Explicit source branch. |

Development placement and branch selection follow the requested name.

| Creation input | Managed placement | Selected branch |
| --- | --- | --- |
| `default` without `--branch` | `<node-apps-root>/<project-slug>/default` | The Project `default_branch`. |
| Another name without `--branch` | `<node-apps-root>/<project-slug>/<name>` | The matching origin branch, otherwise the existing local branch, otherwise a new branch from the fetched `default_branch` commit. |
| Any name with `--branch` | The placement for the requested name | The requested origin branch, otherwise the existing local branch, otherwise a new branch from the fetched `default_branch` commit. It need not match the Instance name. |

```bash
orbit instance:create 4 7 default
orbit instance:create 4 7 feature-one --branch=release --domain=feature.example.test
orbit instance:create 4 7 t3-1a2b3c4d --branch=t3code/1a2b3c4d
```

A requested origin branch keeps its existing selection behavior. Orbit does not reset an existing local branch to the default commit. A missing fetched `default_branch` when required returns `instance.branch_resolution_failed`, not a different fallback branch. An invalid Git branch name returns `validation.failed` before source changes.

A create that fails before activation removes its owned resources and Instance row without teardown. The response keeps the original error code. Once cleanup completes, a new create can select a different branch. If an interruption or incomplete cleanup leaves a pre-activation Instance, an identical retry resumes it; a retry that changes the root or `--branch` returns `instance.placement_conflict`. Incomplete cleanup reports `details.cleanup = "incomplete"` and a recovery command. [`instance:destroy`](#orbit-instancedestroy) accepts `reserved`, `checkout_prepared`, and `source_resolved` for [pre-activation removal](/reference/instance-removal#pre-activation-removal).

<Note>
The Instance becomes active once Orbit has prepared the source, PHP runtime, Laravel URL, and Route. Setup runs after that. A successful create response also means every setup step succeeded; an empty list counts as success. The application can still fail for other reasons.
</Note>

A failed setup step removes the new Instance after the teardown steps run. See [Instance setup and teardown](/reference/instance-setup#run-setup).

## orbit instance:rename

Record a Git branch that is already checked out, change the Instance's Route domain, or do both. Only an active development checkout is eligible. This command does not rename the Instance, move its directory, change its starting commit, or run Git commands that alter the checkout.

```bash
orbit instance:rename <instance> [--branch=BRANCH] [--domain=HOST] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Positive numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--branch=BRANCH` | unchanged | Record this local branch. Symbolic `HEAD` must already name it. |
| `--domain=HOST` | unchanged | Replace the domain of the Instance's own single-target Project Route, including a generated Route. |
| `--json` | off | Return one Instance JSON document, or one error document, without prompts or progress. |

Supply at least one of `--branch` and `--domain`. Supplied values must be nonempty strings. The command needs no `--yes` or `--force`: it records intent and converges the Route without discarding source. In a terminal, an omitted Instance selector uses the shared Instance selection prompt; in noninteractive or JSON mode it returns `instance.id_invalid`. There is no implicit branch or domain selection.

Rename the branch locally before recording it. Orbit checks the managed checkout's identity and the supplied branch locally on the Node, with no origin access. A dirty or unpublished branch can be recorded. Normal removal still requires clean, published source.

```bash
# In the Instance checkout:
git branch -m t3code/login-redirect
orbit instance:rename 1 --branch=t3code/login-redirect
orbit instance:rename 1 --domain=login-redirect.acme.test
orbit instance:rename 1 --branch=t3code/login-redirect --domain=login-redirect.acme.test --json
```

A changed branch updates `selected_branch` and `branch_override`. Recording the already recorded branch is a no-op that preserves its existing override. A domain-only request does not change either branch field. The domain follows [Route replacement](/reference/routes#change-an-instance-route-domain); Laravel's stored `APP_URL`, `.env`, and cached configuration follow it. Generated provenance stays generated, so a later Project slug or effective-TLD change can recompute the domain.

All supplied fields, checkout identity, the supplied branch, and domain availability are checked before mutation. A combined request with a branch mismatch or domain conflict changes nothing. A changed branch is recorded only after any requested domain convergence succeeds. An identical retry after a completed rename returns the Instance without creating an additional Route, including when the caller lost the success response. An incomplete Route replacement follows the existing recovery rules. If a full rollback before cutover deleted the failed replacement, an identical retry can reserve a fresh replacement; the changed branch is still recorded only after domain convergence succeeds. A different domain while replacement recovery is incomplete is refused. See [recorded branch behavior](/domains/applications#record-a-renamed-branch) and [Route recovery](/reference/routes#resume-or-refuse-a-change).

### Human output

The command shows truthful waiting feedback during the synchronous request, then the shared Instance detail tree. Project and Node labels use their slug and name. It does not show a Process selector or invent remote progress stages. The following abbreviated example shows the fields affected by a combined rename; the full tree also has the usual ID, placement, root, and Vite-port fields:

```text
┌  Instance: dev
│
├  Project           acme
│
├  Node              app-dev
│
├  Selected branch   t3code/login-redirect
│
├  Branch override   t3code/login-redirect
│
├  Domain            login-redirect.acme.test
│
└  URL               https://login-redirect.acme.test
```

A refusal shows the stable error code and a useful message, with no success tree. For example, `instance.branch_not_checked_out` tells the caller to check out the requested branch first. Success exits with status `0`; a refusal or failed convergence exits with status `1`.

### JSON and API output

The API is `POST /api/v1/instances/{instance}/rename` with optional `branch` and `domain`, for example `{"branch":"t3code/login-redirect","domain":"login-redirect.acme.test"}`. At least one field is required; null, empty, and wrong-type values are invalid. The MCP tool is `instance-rename`, with `instance_id` and the same optional fields.

Success returns the full Instance shape used by `GET /api/v1/instances/{instance}` and `instance:show --json`, including Project and Node identities, source and placement fields, `route`, `domain`, `url`, removal and transfer state, deploy steps, and `request_id`. It has no rename-specific envelope. This abbreviated JSON example selects fields from that response, not a separate response schema:

```json
{
  "id": 1,
  "name": "dev",
  "project": {"id": 1, "name": "Acme", "slug": "acme"},
  "node": {"id": 1, "name": "app-dev"},
  "source_layout": "checkout",
  "checkout_path": "/srv/orbit/apps/acme/dev",
  "selected_branch": "t3code/login-redirect",
  "branch_override": "t3code/login-redirect",
  "status": "active",
  "domain": "login-redirect.acme.test",
  "url": "https://login-redirect.acme.test"
}
```

Failures use the existing error shape, with the stable code under `error.code`, the message under `error.message`, and the request correlation ID under `error.request_id`. JSON output contains no human tree, prompt, or animation.

### Refusal codes

| Code | Meaning |
| --- | --- |
| `validation.failed` | Neither field was supplied, or a supplied value is null, empty, wrong-type, or an invalid Git branch name. |
| `instance.id_invalid` | The CLI Instance selector is missing in noninteractive mode or is not a positive numeric ID. |
| `instance.rename_unsupported` | The Instance is production or is not a development checkout, including linked worktrees. |
| `instance.rename_inactive` | The development checkout is not active and is not being removed. |
| `instance.lifecycle_busy` | Another lifecycle or environment operation owns the Instance, including removal, an incomplete transfer, or clone. |
| `instance.source_identity_invalid` | Local inspection cannot establish the managed checkout's path, ownership, layout, or Project origin identity. |
| `instance.branch_not_checked_out` | The supplied branch is not the current symbolic `HEAD`, including detached `HEAD`. |
| `instance.route_required` | A domain was supplied, but there is no own single-target Project Route. |
| `route.domain_invalid` | The requested domain is invalid. |
| `route.domain_conflict` | Another Route owns the normalized domain, or it is a reserved domain. |
| `route.domain_change_conflict` | A different domain replacement is already in progress. |
| `instance.source_profile_missing` | Domain convergence lacks the recorded source profile needed for URL synchronization. |
| `env.owner_changed` | Route targets or environment ownership changed while acquiring the operation owner. |
| `route.reconciliation_required` | An incompatible Route or placement reconciliation is in progress. |
| `route.domain_change_failed` | Route projection or URL synchronization failed; inspect Route failure details and retry the same request. |

Authentication, access and missing-record errors, and more specific Route projection errors retain the shared API error contract. A preflight refusal changes nothing. Infrastructure failure during convergence follows Route rollback before cutover and forward recovery after cutover; it is not a promise of atomic rollback across the Node and Gateway.

## orbit instance:register

Adopt the current Git checkout or worktree as a managed Instance of an existing Project. Run it on the app-dev Node that holds the source.

```bash
orbit instance:register [options]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--path=PATH` | the current directory | Existing Git checkout or worktree. |
| `--include-worktrees` | off | Adopt the checkout and every linked worktree as one preflighted set. |
| `--project=ID` | resolved from the origin | Existing numeric Project ID. |
| `--name=NAME` | inferred | Non-default Instance name. |
| `--root=PATH` | the Project root | Relative web-root override for this Instance. |
| `--domain=HOST` | generated | Explicit Route domain for the primary source. |
| `--yes` | off | Confirm transfer of the source into Orbit ownership without prompting. |
| `--setup` | off | Run the Project setup steps after adoption. A failed step leaves the Instance and the checkout in place. |

The CLI refuses a directory outside Git and an origin with credentials before it sends a request. The Gateway finds the Project by repository identity, checks the source on the caller's Node, moves it into its managed path, and provisions it as `instance:create` does. See [Register an existing checkout](/domains/applications#register-an-existing-checkout).

Registration never creates a Project. When no Project owns the repository, it fails with `instance.project_missing`. Run [`project:create`](/cli/project#orbit-projectcreate) first.

In a terminal, the CLI asks for default-No consent that names the source. JSON and noninteractive calls need `--yes`. Cancellation leaves the source unchanged.

```bash
cd ~/apps/acme
orbit instance:register
orbit instance:register --path=/srv/orbit/apps/acme/main --include-worktrees --yes --json
```


| Argument | Required | Meaning |

## orbit instance:logs

Return the end of the Instance's application log, `storage/logs/laravel.log` or the newest `laravel-*.log`, or follow new lines as they are written. Stored environment values and credential-shaped data are redacted. [Instance logs](/reference/instance-logs) describes the file and the redaction.

```bash
orbit instance:logs <instance> [--lines=COUNT] [--follow] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--lines=COUNT` | `100` | Number of lines, from 1 through 1,000. With `--follow`, the number of earlier lines to print first. |
| `--follow` | off | Keep printing new lines until Ctrl-C. |

`--follow` works as it does for [`process:logs`](/cli/process#orbit-processlogs): the CLI opens a [live log stream](/reference/live-logs), and it polls the one-shot read every 5 seconds when the Gateway cannot open one. A production Instance log is always read over SSH: the CLI prints `Following over SSH; polling every 5 seconds.` and polls from the start. The JSON output has the same shapes, with reason `ssh_only` in the notice. Without `--follow`, `--json` returns `{ id, name, lines, logs, request_id }`.

```bash
orbit instance:logs 12 --lines=50
orbit instance:logs 12 --follow
```

## orbit instance:destroy

Remove an Instance with its Route, Processes, Schedules, and runtime. A development removal runs the teardown steps first and deletes the checkout. See [Instance removal](/reference/instance-removal).

```bash
orbit instance:destroy <instance> [--yes] [--force] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Meaning |
| --- | --- |
| `--yes` | Confirm removal without prompting. Required for JSON and noninteractive calls. |
| `--force` | Delete dirty or unpublished development source after identity checks pass, and accept a checkout together with its registered linked worktrees. |

Interactive removal defaults to No. `--force` does not supply consent.

Normal removal refuses dirty source, a `HEAD` that no origin branch or tag contains, and a checkout with registered linked worktrees. `--force` waives only those three refusals. The source identity checks apply in both modes.

```bash
orbit instance:destroy 12
orbit instance:destroy 12 --force
```

<Warning>
Production removal keeps `releases/`, `.env`, `database.sqlite`, and the local PHP-FPM tuning. Repeat the same command to resume an interrupted removal. A failed teardown step keeps the Instance, and the next `instance:destroy` runs the teardown list again.
</Warning>

## orbit instance:clone

Clone a candidate into a prepared production Instance. The candidate supplies source, stored environment values, and an optional SQLite snapshot. The Project supplies production Process and Schedule definitions.

```bash
orbit instance:clone <candidate> <node> <name> --preview-name=NAME [options]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `candidate` | yes | Numeric candidate Instance ID. |
| `node` | yes | Numeric destination Node ID with the active `app-prod` role. |
| `name` | yes | Target production Instance name. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--preview-name=NAME` | required | Preview name that the Gateway combines with the destination Node TLD. |
| `--branch=BRANCH` | the candidate branch | Target branch that must exist in the Project repository. |
| `--sqlite-source-path=PATH` | none | Absolute path to one SQLite database on the candidate to seed `database.sqlite`. |

Give the production Node a TLD with `node:add --tld` first: `shop.com` on a Node with TLD `prod.orbit` becomes the preview `shop.com.prod.orbit`. The candidate must be clean, and its commit must be in the Project repository.

```bash
orbit node:add production production.example --role=app-prod --tld=prod.orbit
orbit instance:clone 12 9 primary --preview-name=shop.com --sqlite-source-path=/srv/orbit/apps/acme/default/database/database.sqlite
```

Cloning ends with an active Instance and no release. Update its environment, record deploy steps, then run `instance:deploy`. See [Instance cloning](/reference/instance-cloning#next-steps).

## orbit instance:update

Change the deployment branch of a production Instance. The Gateway stores the branch and does not change deploy steps or start a deployment.

The human result shows the accepted deployment branch and the currently selected source branch. JSON returns the existing Instance response; its `selected_branch` describes the source, not the newly stored deployment setting.

```bash
orbit instance:update <instance> --branch=BRANCH [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Meaning |
| --- | --- |
| `--branch=BRANCH` | Deployment branch. A later Project default change does not replace it. |

The Gateway refuses a development Instance with a bounded conflict before it stores a branch.

## orbit instance:deploy-step:create

Record one named deploy step on a production Instance. The Gateway stores it at the end of its phase unless you place it.

```bash
orbit instance:deploy-step:create <instance> <name> --command=COMMAND [options]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |
| `name` | yes | Step name: 1 through 63 lowercase letters, digits, or hyphens, unique within the Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--command=COMMAND` | required | Command the Gateway runs as the production user from the fresh release. |
| `--phase=PHASE` | `before_activation` | `before_activation` or `after_activation`. |
| `--timeout=SECONDS` | `300` | Timeout from 1 through 900 seconds. |
| `--before=NAME` | none | Place before this step in the same phase. Exclusive with `--after`. |
| `--after=NAME` | none | Place after this step in the same phase. Exclusive with `--before`. |

```bash
orbit instance:deploy-step:create 15 install --command="composer install --no-dev --optimize-autoloader"
orbit instance:deploy-step:create 15 migrate --command="php artisan migrate --force" --after=install
orbit instance:deploy-step:create 15 restart-queue --command="php artisan queue:restart" --phase=after_activation
```

The Gateway refuses a duplicate name, a placement that names an unknown step or a step in another phase, a thirty-third step, a timeout over 900 seconds, or a step-timeout sum over 3,600 seconds.

## orbit instance:deploy-step:list

## orbit instance:deploy

Deploy the configured branch of a production Instance. The Gateway creates a fresh release, fetches the branch, synchronizes stored environment values, runs the `before_activation` steps, atomically replaces `current`, refreshes the PHP runtime cache, and runs the `after_activation` steps.

```bash
orbit instance:deploy <instance> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

Human output shows a progress tree. The deploy phases the Gateway always sends appear up front; named deploy steps and the PHP cache refresh phase reveal only when their phase starts. Glyphs and color show waiting, running, success, failure, and not-reached states, and active indicators alternate while work is in progress. Standard output and standard error from application commands appear labeled and escaped, and print above the tree without redrawing it, while their step runs.

On failure the tree marks the last reached step as failed, with the error code shown under it, even when the Gateway's failed boundary has no step of its own (an activation or cache-refresh failure during a rollback, for example). Every later step shows orange with a dim "Not reached." label under it, and the footer turns red. The final lines add the failed boundary, the error code, the selected release when available, and the request ID. `--json` writes the same events as NDJSON, one event per line, without prompts or prose.

Pressing Ctrl-C closes the connection at once, including during a step with no output yet: the CLI does not wait for the Gateway to finish that step first. The tree marks the current step failed and shows a red "Operation interrupted." footer; JSON mode ends the stream with no result line. Either way the CLI submits no second request.

| Event type | Fields |
| --- | --- |
| `phase` | `phase` is `source_preparation`, `environment_sync`, `before_activation`, `activation`, `php_refresh`, `after_activation`, or `rollback`. `step_name` is present only for a named step. |
| `output` | `stream` is `stdout` or `stderr`. `data_base64` carries at most 16 KiB of decoded bytes. |
| `result` | `status` is `succeeded` or `failed`, with nullable `failed_step`, `error_code`, and `selected_release`. This is the final line. |

Every event carries `type`, a monotonically increasing `sequence`, and the `request_id`. A failed `result` stays a `result` event; the CLI uses the one-line error envelope only when the Gateway refuses the command before the stream opens or when the stream is malformed or truncated.

| Stream outcome | Exit status |
| --- | --- |
| The final event is a succeeded result. | `0` |
| The final event is a failed result. | Nonzero. The command names the failed boundary and the selected release when the result includes one. |
| The stream is malformed, truncated, or ends without a result. | Nonzero. The CLI never infers success from earlier events. |
| You press Ctrl-C. | Nonzero. The CLI closes its connection and submits no second request. |

```bash
orbit instance:deploy 15
orbit instance:deploy 15 --json > deploy.ndjson
```

A failure during release fetch, environment synchronization, or a `before_activation` step leaves the prior `current` selected. A failure during the PHP cache refresh or an `after_activation` step leaves the fresh release selected. Deployment, rollback, deploy-step changes, environment changes, and removal share one operation owner per Instance, so a competing request waits or returns a busy refusal.

<Note>
A development Instance cannot be deployed. With `--json` the stream ends with a failed `result` whose `error_code` is `deployment_config.unavailable`.
</Note>

## orbit instance:database:add

Add a registered Database connection on an Instance and write prefixed keys into its stored environment configuration.

```bash
orbit instance:database:add <slug> --instance=SELECTOR [--prefix=PREFIX] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `slug` | yes | Database connection slug from `database:list`. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--instance=SELECTOR` | required | Positive Instance ID or exact Route domain. |
| `--prefix=PREFIX` | `DB` | Uppercase key prefix that starts with a letter, at most 32 characters. |

For mysql and pgsql the Gateway writes `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, and `DB_PASSWORD`. For sqlite it writes `DB_CONNECTION=sqlite` and `DB_DATABASE` as the absolute path, plus username and password only when stored. When the connection names the same Node as the Instance and aligns with a Node-owned Docker Process, the Gateway writes host `127.0.0.1` and the published host port.

```bash
orbit instance:database:add app --instance=12
orbit instance:database:add reporting --instance=shop.example.test --prefix=REPORTING
```

Add changes stored configuration only. Run `orbit env:sync --instance=SELECTOR` to install it in the workload `.env`.

| --- | --- | --- |

## orbit instance:analytics:enable

Publish the tracking hosts that send an Instance's visits to the analytics role.

```bash
orbit instance:analytics:enable <instance> [--host=HOST]... [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--host=HOST` | `analytics.<instance domain>` | A tracking host. Repeat it for more, up to ten. |

```bash
orbit instance:analytics:enable 12
orbit instance:analytics:enable 12 --host=stats.example.com --host=analytics.shop.example.com
```

The command sets the exact host set: the Gateway publishes each named host that is missing and removes each tracking host of the Instance that you did not name. Naming the hosts that already exist changes nothing. Each host is a Route that answers only `/js/*` and `/api/event`, served wherever the Instance's own domain is served; the [Analytics role](/reference/analytics#publish-a-tracking-host) page owns that contract.

Human output lists each host with its Route and status, the DNS record to create for it, and the script tag to add to the Project. JSON returns `instance_id`, `enabled`, `domain`, `dashboard_url`, `hosts`, and `snippet`. You still create the site in Plausible yourself.

| Error code | Meaning |
| --- | --- |
| `analytics.role_missing` | No Node has an active analytics role. |
| `analytics.domain_required` | The Instance does not serve a domain yet. |
| `analytics.host_taken` | Another Route already uses a named host. |
| `validation.failed` | A host is not a lowercase DNS name, is reserved, is repeated, or more than ten hosts were named. |

The output has the same shape as [`instance:analytics:enable`](#orbit-instanceanalyticsenable). An Instance without tracking hosts reports tracking as disabled, with no hosts and no script tag.
