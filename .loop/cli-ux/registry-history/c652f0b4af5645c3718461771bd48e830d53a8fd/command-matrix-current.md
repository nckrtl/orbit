## Contract definitions

- `current_json`: Preserve current command-specific success DTOs and error.code/message/details?/request_id. Do not copy legacy success.data/meta or error.meta envelopes.
- `typed_http`: Operational requests remain typed SDK HTTP calls. Do not add SSH, remote shell or generic executors to product commands. Explicit local trust/DNS and local profile/extension operations retain their bounded adapters.
- `existing_signature`: Current command signatures are exact-tested. Record intentional input or consent changes explicitly; do not assume legacy prompting or --force semantics.
- `local_profile`: Uses local Orbit profile configuration rather than an operational Gateway request.
- `active_profile_force`: --force permits removing the active profile and clearing active selection; it is not merely a generic confirmation bypass.
- `trust_local`: Explicit visible local trust operation. --accept-ca-change accepts a changed Gateway CA; preserve this distinct trust decision.
- `dns_local`: Explicit visible macOS local resolver for a one-label development TLD or multi-label exact private Route name. --reset resets the selected name and is not consent. TLD JSON uses tld; exact-name JSON uses hostname. Preserve Linux refusal and native dependency/privilege boundaries.
- `extension_local`: Uses private local extension state. Herdr command visibility and invocation guards change when the extension is enabled or disabled.
- `numeric_target`: Current signature accepts an explicit positive numeric resource ID; generic prompting must not silently change identifier semantics.
- `cluster_consent`: Interactive confirmation defaults to No; JSON/noninteractive removal requires --force.
- `node_reference`: Where supported, Node reference resolution accepts positive numeric ID or exact registered name through Gateway lookup.
- `node_remove_consent`: Resolve the existing Node before requiring consent. Missing targets must remain not-found rather than consent-required. Interactive confirmation defaults to No; --force supplies consent.
- `node_offline`: --offline is a separate explicit operational claim, not a consent flag.
- `node_role_consent`: Role removal has existing preview/confirmation behavior. Preserve --force, --purge-data and --offline distinctions.
- `node_access`: Consumer and serving Nodes are explicit numeric IDs. CLI does not decide access, Gateway identity or role authority.
- `node_access_consent`: Access removal requires default-No interactive confirmation or --force.
- `instance_force_override`: --force authorizes dirty/unpublished source deletion after identity checks. Do not conflate source-safety override with ordinary destructive consent.
- `source_recovery`: --recover-source-profile controls explicit source-profile recovery, not generic consent.
- `registration`: Registration examines source facts and may prompt for unresolved default branch/root; noninteractive registration requires unresolved values as options. Ownership transfer is a separate confirmation decision.
- `database_secret`: Database configuration may receive passwords, but ordinary result output must preserve credential redaction and password-presence semantics.
- `database_consent`: Default-No interactive confirmation or --force is required for database destruction or attachment removal.
- `attachment_target`: Requires explicit --instance targeting; attachment prefix and database slug are separate inputs.
- `environment_explicit`: Explicit numeric AppInstance ID or exact Route hostname only. Never select a target, display values, read/write local environment files, resolve placeholders, restart processes or refresh application caches.
- `environment_replace`: --replace permits stored-key conflicts during import; preserve existing values otherwise.
- `environment_strings`: Preserve quoted empty, multiline, false, zero and placeholder-containing values as strings.
- `definition_target`: App-owned runtime definitions and concrete runtime resources are distinct. Preserve --app/--for and current ID/name targeting rules.
- `process_target`: Preserve process target exclusivity and current App/Node/AppInstance behavior; do not add target discovery through generic UX helpers.
- `bounded_process_logs`: One bounded log tail with --lines 1..1000; no continuous follow stream. Preserve log sanitization and request ID.
- `schedule_explicit`: schedule:create requires exactly one of --app, --node or --instance in every mode. Never discover or prompt for a target. App definitions require --for; --no-start is AppInstance-only.
- `schedule_uuid`: Concrete Schedule operations use a Schedule UUID, distinct from App definition names.
- `schedule_no_complete`: Completion is internal Node-authenticated API/SDK transport. Never expose schedule:complete.
- `bounded_schedule_logs`: One bounded log tail with --lines 1..1000; no continuous follow stream.
- `tool_install_prompt`: Node remains explicit. Interactive manager choices come from that Node's supported active/uninstalled managers. Missing package may be prompted. JSON/noninteractive calls must supply Node, manager and package.
- `tool_gateway_policy`: Tool manager execution, SemVer policy and infrastructure remain Gateway responsibilities.
- `metrics_enable_prompt`: metrics:enable permits Node selection when omitted in human interactive mode. JSON and noninteractive input must provide the target. Node ID or exact registered name remains accepted.
- `metrics_disable`: Noninteractive/JSON disable requires --force. --purge-data also requires --force; interactive nonforced disable shows preview and default-No confirmation.
- `metrics_credentials`: Explicit credential-delivery command intentionally returns URL, username and password. --reset rotates the password. This is an exception to ordinary secret-free output, and proof must use disposable credentials with controlled artifacts.
- `herdr_enabled`: Supported public command only when Herdr extension is enabled; hidden and guarded otherwise.
- `herdr_target`: Requires explicit session name and Node reference; resolves the named session through the Gateway.
- `herdr_destroy`: --accept-termination explicitly accepts live-pane termination. Destruction removes the session from Orbit and destroys its Process only when Orbit manages it.
- `herdr_restart`: --handoff requests live handoff only when inspected server support permits it.
- `herdr_grant`: Issues a short-lived receive-only observation grant rather than attaching a CLI stream. Requires pane, terminal, viewport and HTTPS origin. Intentionally returns observer URL; handle proof artifacts accordingly.
- `doctor_sync`: Verify-only synchronous read-only comparison. No repair, adoption, progress stream or persisted run. Local liveness must not invent remote milestones or percentage.
- `doctor_scope`: Preserve selected scope, family ordering, bounded findings, resource-based checked counts, and unhealthy exit status.
- `deployment_ndjson`: --json already emits NDJSON phase/output/result records with sequence and request_id. Do not replace with a final envelope or require --stream-json without an explicit compatibility decision.
- `deployment_bytes`: JSON output bytes use data_base64; current human bytes use escaped terminal-safe strings. Preserve binary/control-character safety and result-derived exit status.
- `deployment_failure`: Retain partial stream evidence, close stream on exit, and distinguish terminal result failure from malformed/interrupted stream.
- `vocabulary`: Use accepted ADR 0071 and the current vocabulary. Do not reintroduce retired Workspace or deployment document/layout commands.
