# Feature plan

Issue: ORB-77
Review verdict: PENDING

## Outcome

Add App-owned Route intent whose ordered AppInstance targets, Node-first hostname, exclusive Node-or-active-Cluster scope, lifecycle values, and related removal and mutation boundaries remain consistent across the Gateway, PHP SDK, and CLI without projecting traffic.

## Code boundaries

In:

- `apps/gateway/database/migrations/*routes*`, `apps/gateway/app/Models/{App,AppInstance,Cluster,Node,Route,RouteTarget}.php`, and `apps/gateway/app/Domain/Routes/**`: add Route and ordered RouteTarget persistence. A Route has restrictive App ownership, a globally unique normalized hostname, immutable `generated` or `explicit` provenance, exactly one mutable nullable-foreign-key XOR Node-or-Cluster scope, and immutable `private` or `public` publication intent. The only lifecycle value this issue writes or returns is `pending`; successful operations keep `failed_step` and `error_code` null, and traffic convergence in ORB-78 owns activation and populated failure metadata. Route targets have a non-negative position unique within the Route, permit several rows without a unique `route_id`, prevent duplicate AppInstances and duplicate target Nodes within one Route, cascade from Route and AppInstance deletion, and retain restrictive scope owners. Relations return targets in position order.
- `apps/gateway/app/Data/Routes/**`, `apps/gateway/app/Actions/Routes/**`, and `apps/gateway/tests/Feature/{Database/RouteMigrationTest.php,Api/RoutesTest.php}`: add typed create, list, show, explicit-hostname-only update, scalar target replacement, target clear, and Route removal behavior. Public create requires one active app-dev target and assigns `explicit` provenance; AppInstance-driven create assigns `generated` unless an explicit hostname was supplied. Generic update can change only an explicit Route's hostname and cannot change App, scope, provenance, publication intent, lifecycle, failure metadata, or targets; scope changes only through desired-state reconciliation. Public v1 returns one nullable target and rejects target arrays or caller-supplied provenance, lifecycle, failure, backend Node, address, URL, or balancing values. Identical normalized creation retries return one Route; conflicting identity or intent and every invalid proposed relationship leave the complete old Route state unchanged.
- `apps/gateway/app/Data/AppInstances/CreateAppInstanceData.php`, `apps/gateway/app/Http/Requests/AppInstances/StoreAppInstanceRequest.php`, `apps/gateway/app/Actions/AppInstances/CreateAppInstanceAction.php`, and `apps/gateway/tests/Feature/Api/AppInstancesTest.php`: accept one optional explicit hostname, preserve the existing managed-clone state machine, and create the explicit or generated private pending Route only after the AppInstance is active. Generate from the Node TLD first and use the active Cluster TLD only when the Node has no TLD; use exact main-branch equality for `<app>.<tld>` and `<instance>.<app>.<tld>` otherwise. Derive Node scope outside an active Cluster and Cluster scope for every active membership, independent of the hostname suffix. A Route failure must not create a partial Route or rewrite active AppInstance source evidence, and an identical AppInstance retry must complete the same Route intent.
- `apps/gateway/app/Domain/Routes/**`, `apps/gateway/app/Actions/Nodes/ProvisionNodeAction.php`, `apps/gateway/app/Actions/Clusters/{UpdateCluster,AttachClusterNode,DetachClusterNode,ClearClusterRouter}Action.php`, and `apps/gateway/tests/Feature/Domain/RouteMutationReconciliationTest.php`: add one locked desired-state reconciler for every Route affected by a proposed Node or Cluster TLD, state, membership, attach, or detach change. Recompute generated hostnames only when the Node-first selected TLD changes, preserve explicit hostnames, and derive scope from proposed active membership even for a TLD-less Cluster. Require an active Router before any Route enters Cluster scope, allow an empty active TLD-less Cluster without one, keep an app-dev Node valid only with a Node TLD or active-Cluster TLD fallback, and allow an app-prod Node with explicit Routes to have neither. Validate every stored ordered target, hostname collision, scope, and required Router before any owner mutation becomes authoritative, then apply the complete owner and Route desired state atomically; integrate the existing Node TLD recovery so every ORB-77 validation or reconciliation failure restores the complete old Route, Node, Cluster, and membership state.
- `apps/gateway/app/Domain/Routes/RouteRemovalGuard.php`, `apps/gateway/app/Actions/Apps/RemoveAppAction.php`, `apps/gateway/app/Actions/Nodes/{RemoveNode,RemoveNodeRole}Action.php`, `apps/gateway/app/Actions/Clusters/{RemoveCluster,ClearClusterRouter}Action.php`, `apps/gateway/app/Actions/AppInstances/RemoveAppInstanceAction.php`, and `apps/gateway/tests/Feature/Domain/RouteRemovalGuardTest.php`: refuse App removal while it owns Routes, Node removal while it is a direct scope or hosts a target, Cluster removal or Router clearing while it scopes a Route, and app-dev or app-prod role removal while its Node hosts a target. Run these guards before force, purge, offline, remote, or destructive work. Create accepts `app_id`, exactly one of `node_id|cluster_id`, `hostname`, `publication`, and scalar `app_instance_id`; update accepts only `hostname`; target set accepts scalar `app_instance_id`. Reject generic scope, publication, provenance, lifecycle, failure, and target updates. Out:

- Keep Gateway DNS, TLS and certificate issuance, Router and workload Caddy rendering, firewall mutation, Route health, request-path forwarding, Route activation, populated failure metadata, and every other traffic projection unchanged. ORB-78 extends this atomic desired-state boundary through DNS, TLS, Caddy, firewall, health, and request-path convergence and owns convergence-driven activation and failure values.
- Keep Ingress listener behavior and public DNS-provider automation unchanged; `public` is stored intent only, and ORB-83 owns public publication.
- Keep the public API, SDK, and CLI limited to one scalar target. Do not expose multiple configured targets or add balancing, weighting, health selection, failover, draining, scheduling, movement, or rebalancing; ORB-84 owns that behavior.
- Do not reconcile App slug or main-branch updates, repository or root changes, environment files, or their projections; ORB-101 owns those App updates. This issue only stores immutable Route provenance and uses current values during creation and Route-affecting Node or Cluster mutations.
- Keep AppInstance source creation, registration, conversion, checkout paths, branches, commits, and removal safety unchanged except for the optional hostname transport, post-activation Route hook, and post-removal target clearing. Preserve ADR 0009's staged conversion and verified-cutover invariant; do not change legacy conversion, `apps/e2e`, `bin/e2e-*`, or any harness behavior.

## Must preserve

- ADR 0023, Route ownership and hostname selection: the Route is the only authoritative hostname owner; explicit input wins; generated development names use the Node TLD first and active Cluster TLD only as fallback; app-dev retains one of those TLDs while app-prod may retain neither.
- ADR 0023, independent routing scope and roles: active Cluster membership selects Cluster scope regardless of hostname or TLD; every Route-owning Cluster has exactly one active Router; workload Caddy still receives the same hostname; private direct workload access does not change scope; public traffic always enters through Ingress; co-located roles keep the same logical path.
- ADR 0023, mutation consistency: every affected Route reconciles before its Node or Cluster TLD, state, membership, attach, or detach mutation becomes authoritative; explicit hostnames remain fixed; only generated names whose selected TLD changes are recomputed; any invalid hostname, scope, target, or required role preserves the complete old Route and owner state.
- ADR 0009, “Close domain ownership and identity”: the App owns Routes; each target references an AppInstance rather than an independent Node; targets remain inside the Route's App and scope; persistence stays one-to-many and ordered; public v1 has one target and no balancing policy; a zero-target Route retains identity and immutable publication intent; generic updates never change the exclusive scope outside reconciliation.
- ADR 0009, AppInstance source and placement decisions: AppInstance remains App plus Node with an independent clone, exact branch and commit evidence, immutable checkout path, refusal-first source removal, and explicit Node placement. Route work must not add private runtime ownership, change source, or infer an independent Cluster input.
- ADR 0009, generated/explicit Route and projection decisions: main and feature shapes remain exact; explicit hostname validation proves no DNS ownership; Router, workload Caddy, certificates, firewall, DNS, health, and request paths remain separate projections; ORB-77 creates only `pending` Routes, while ORB-78 owns convergence-driven activation and failure metadata across those projections.
- ADR 0009, “Convert legacy resources in stages”: legacy Instance and Workspace reads remain compatible; conversion still stages source, runtime, and routing without traffic change, cuts over only after the replacement state is verified, restores legacy traffic on cutover failure, and removes legacy source only after trusted traffic succeeds.
- ADR 0017 where ADR 0023 leaves it in force: Cluster membership remains optional; each Route stores one exclusive scope and can retain zero targets; Node-scope targets remain on one Node and Cluster-scope targets remain on member Nodes; desired-state mutations remain idempotent and refuse partial cutover; legacy conversion preserves source and placement. ADR 0023 controls hostname precedence, active-Cluster scope, Router requirements, and public exposure where the records differ.
- ADR 0016, generated provenance and App update boundaries: immutable stored provenance makes later slug reconciliation possible; explicit names never change implicitly; current main-branch equality affects only new Route creation; this issue does not change App identity, source defaults, checkout paths, runtime roots, environment files, or projection publication.
- ADR 0011, “Separate Ingress, Router, and workload ownership” and “Preserve Route independence and defer balancing policy”: Ingress never receives backend placement; a public Route has no direct workload endpoint; Route targets expose no Node/address/URL escape hatch; persistence prevents two targets on one Node; public v1 selects no balancing, health, stickiness, failover, or draining policy.
- ADR 0004, “Keep Doctor verify-only,” “Use eight ordered families,” and “Partition every persisted model”: Route and RouteTarget are typed `instance` inputs exactly once, not checked resources or a ninth family; Doctor adds no mutation, observation, issue, report, or stored state.
- Existing AppInstance tests remain green for `reserved -> checkout_prepared -> source_resolved -> active`, source identity, immutable placement, active retry, removal refusal, and exact source cleanup. Route creation runs only after successful activation; a Route error must never weaken those checks, rewrite their evidence, or expose repository diagnostics.
- Existing Cluster, Node, and role tests retain optional membership, same-type TLD uniqueness, active cross-scope conflict checks, role ownership, and all pre-existing removal rollback and force/purge/offline behavior except where ADR 0023 requires the new Route-aware desired-state result.
- `TopLevelJsonObjectInspector` still rejects malformed objects, duplicate top-level keys, and unsupported fields. Every new endpoint keeps active-peer authentication, explicit binary node access, numeric route parameters, request correlation, bounded errors, recursive redaction, and sanitized activity data.
- Legacy `InstanceData` still returns `hostname` and `certificate_mode`; `WorkspaceData` still returns `hostname`; neither legacy model, API identity, source, runtime, nor conversion path adopts Route state.
- The SDK remains framework-neutral Saloon transport, preserves explicit non-null values, omits only contract-defined nulls, retains TLS verification, request correlation, response bounds, redaction, and standard error envelopes, and exposes no raw response escape hatch or Gateway policy.
- The CLI remains stateless and HTTP-only, offers `--json` on every Route command, keeps deterministic output and request-ID errors, and performs no SSH, infrastructure, policy, or projection work.
- Dependency manifests, the E2E harness, issue proof files, GitHub, Linear, production release, and unrelated components remain unchanged.
