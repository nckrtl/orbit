Issue: ORB-219

## Outcome

The Gateway synchronously deploys a production AppInstance's configured branch or selects retained code for rollback, streams bounded application output, and reports the selected release and failure boundary without automatic recovery.

## Code boundaries

In:
- New deployment orchestration and result types under `apps/gateway/app/Domain/AppInstances/Deployment/**` and synchronous `DeployAppInstanceAction.php` and `RollbackAppInstanceAction.php` under `apps/gateway/app/Actions/AppInstances/`: capture one immutable configuration at invocation start; accept no commit for deploy and one retained release name for rollback; coordinate release preparation, environment synchronization, ordered step execution, atomic activation, PHP cache refresh, failure-boundary classification, cancellation, and the final selected-release result without persisting a run.
- A narrow production deployment contract and native adapter under `apps/gateway/app/Domain/AppInstances/Deployment/**` and `apps/gateway/app/Infrastructure/AppInstances/**`, with bounded extensions to `ProductionReleaseLayout`, `RemoteProductionAppInstanceSourceLifecycle`, `AppInstance`, `AppServiceProvider`, and their focused tests: authenticate the recorded production home and source, create one fresh owned release from the invocation's configured branch, bind the checkout for the invocation, validate and atomically replace `current`, inspect the selected release, update the existing `checkout_path` placement after selection, and validate retained release names, source ownership, and effective-root containment for rollback.
- `apps/gateway/app/Infrastructure/Processes/**`, `apps/gateway/app/Infrastructure/Ssh/**`, and their focused unit tests: add an invocation-local stdout/stderr event sink and cancellation signal; split process reads into ordered single-stream event values of at most 16 KiB (16,384 bytes); retain the latest 64 KiB (65,536 bytes) independently for stdout and stderr in the final `CommandResult`; leave exact-limit output complete; set `truncated: true` and discard only older retained bytes when either stream exceeds its limit; cap every command and the complete deployment; and terminate the locally and remotely owned process group before returning from timeout or cancellation.
- The deployment step executor under `apps/gateway/app/Infrastructure/AppInstances/**`: send each configured command through protected stdin to a fixed non-interactive shell, run from the prepared release as the recorded production Unix user, preserve exact step order, emit events tagged with step and stream whose values never exceed 16 KiB, preserve the byte order across split events, and never place command or output bytes in infrastructure argv, generic diagnostics, or persistent state.
- Existing `AppInstanceDeploymentConfigResolver`, `SynchronizeAppInstanceEnvironmentAction`, `AppInstanceEnvironmentOperationLock`, `ProductionPhpRuntimeManager`, and production source/layout contracts: reuse the current validated configuration, protected environment synchronization, shared AppInstance mutation owner, exact dedicated-runtime cache refresh, and release-layout ownership instead of duplicating those policies; allow a concurrent configuration update to affect only a later invocation.
- `apps/gateway/tests/Feature/Domain/DeployAppInstanceTest.php`, `DeploymentOperationExclusionTest.php`, focused infrastructure tests under `tests/Feature/Infrastructure/AppInstances/`, existing production provisioning/cloning/show/runtime tests, and process/SSH unit tests: cover branch pinning, full ordering, empty steps, first deployment, selected placement, both failure sides, output timing, 16,384/16,385-byte event boundaries, independent 65,536/65,537-byte retained-stream boundaries and tail truncation, deadlines, process-group cleanup, every competing mutation, rollback exclusions, redaction, no automatic invocation, and continuity-preserving atomic selection.

Out:
- HTTP streaming transport stays unchanged; the new actions expose invocation-local events to a later transport without adding a route, controller, SDK request, CLI command, queue, Agent, or background job.
- Automatic retries stay unchanged; an interrupted or failed application command stops the invocation and is never resumed or replayed.
- Deployment history and output storage stay unchanged; no deployment-run table, Activity output copy, durable event stream, or earlier step-configuration snapshot is added.
- Application recovery stays operator-owned; Orbit does not infer maintenance, health, dependency, asset, cache, migration, process-restart, or recovery commands.
- Data rollback stays unchanged; deployment and code rollback do not restore or rewrite environment side effects, database files, schemas, or application state.
- Automatic release deletion stays unchanged; new and previously retained releases remain available until separate explicit retention work exists.
- `packages/php-sdk/`, `apps/cli/`, `apps/docs/` console code, `apps/e2e/`, and `bin/e2e-*` stay unchanged; discovery uses the prepared topology through existing commands and adds no proof plan, fixture, or harness action.

## Implementation order

1. Add failing domain tests for one immutable deployment configuration, explicit-only invocation, empty steps, exact phase order, first selection, both failure sides, rollback exclusions, selected placement/results, and no run persistence; define the minimal deployment request, event, boundary, result, cancellation, deadline, and remote-operation contracts those tests require.
2. Extend the process and SSH invocation contracts with an optional output sink and cancellation check; split each process read into ordered, same-stream event values no larger than 16,384 bytes; retain the latest 65,536 bytes independently for each final output stream; report no truncation at exactly 65,536 bytes and `truncated: true` with only the older bytes discarded above it; make the native runner terminate the owned local process group on timeout, cancellation, or sink failure; propagate these controls through SSH; and preserve protected-input behavior and the same 65,536-byte default for existing callers. Add explicit 16,384/16,385 and 65,536/65,537 boundary tests for both streams.
3. Implement the production deployment adapter: validate recorded home, release layout, source identity, user, branch, and roots; prepare a uniquely named fresh release from the configured remote branch; return its fixed commit and name; run protected application scripts through the fixed shell from that release; publish and inspect `current` atomically; and validate retained rollback targets without scanning or accepting paths outside the owned release directory.
4. Implement the deploy coordinator under the existing AppInstance operation owner: refresh and validate the production placement, capture configuration once, set the combined budget, prepare the release, call protected environment synchronization, run pre-activation steps, activate and update existing placement state, refresh PHP only when recorded, run post-activation steps, stop on the first failure, and return the observed failure side and selected release without retry or inferred recovery.
5. Implement rollback through the same owner and selection/cache/result path while bypassing fetch, environment synchronization, and steps; add domain and infrastructure coverage for traversal, ownership, web-root, PHP/non-PHP, data, and remote-ref boundaries.
6. Add multi-process exclusion tests that race deploy and rollback with each other and every existing named mutation; keep configuration replacement outside the exclusion but prove a replacement after invocation capture changes only the next deploy. Add first-deploy/show, provisioning/cloning, Activity/redaction, no-history, and continuous-request regression coverage.
7. After independent plan approval, acquire discovery and execute all eight named observations. Record reproducible evidence in `.loop/development.md`, restore controlled failures, and run topology verification.
8. Run the focused Gateway tests, `cd apps/gateway && composer check`, documentation verification, useful TIA feedback, and `git diff --check`; commit the clean candidate for the retained Builder's exact-head root `composer check` and later implementation handoff.

## Must preserve

- ADR 0034: valid Composer metadata remains the sole PHP-project signal; Orbit still selects the highest supported compatible PHP version, defaults an unconstrained PHP project to PHP 8.5, exposes no user-selected AppInstance PHP version, prepares no PHP for a non-PHP source, and leaves PHP package ownership with the Node application role. Deployment consumes the recorded classification and runtime; it does not reclassify or select PHP.
- ADR 0044: the Gateway remains the encrypted authority for one validated value per AppInstance key; values and reference expressions stay out of normal responses, Activity, and diagnostics; import remains explicit and conflict-safe; stored updates remain separate from workload synchronization; and deployment reuses destination-specific reference resolution, literal preservation, recorded placement and identity, pre-decryption access/path/capacity checks, complete atomic file replacement, unresolved-reference refusal, and failure preservation without importing local edits.
- ADR 0044: environment synchronization itself still runs no application command, cache refresh, or process restart. The deployment coordinator invokes that existing operation first and owns the separate later application and cache steps.
- ADR 0045: each production Unix user keeps a separate PHP-FPM master, service, pool, socket, and OPcache while installed packages remain shared; deployment refreshes only the recorded owning service without reload, verifies completion, and never touches another user's service or cache.
- ADR 0045: production runtime identity and provisioning remain Orbit-owned; local tuning remains operator-owned, starts from defaults, stays separate from generated identity, and survives deploy and rollback; effective configuration and associations remain validated; no tuning moves into App or AppInstance storage; existing content remains intact.
- ADR 0046: Orbit owns release preparation, atomic activation, and explicit code rollback inside the recorded home; the AppInstance's captured branch and ordered steps drive one explicit invocation; every deploy fetches the latest branch into a fresh release and keeps that checkout even if the remote advances; and no caller commit selector is added.
- ADR 0046: `.env` and optional SQLite remain outside replaceable releases, the effective web root remains inside selected code, stored environment synchronization precedes agent-selected ordered steps, Orbit inserts no commands, commands run as the AppInstance user with bounded streamed output, activation waits for every pre-step, cache refresh follows the switch and precedes post-steps, and non-PHP targets remain runtime-free.
- ADR 0046: failure before the switch leaves prior code selected; cache or post-step failure leaves new code selected; results report the boundary without automatic rollback, retry, resume, or recovery; rollback selects retained code and refreshes only its runtime; the operating agent retains schema compatibility, data recovery, application recovery, and rollback-command ownership.
- ADR 0046: deployment and rollback never replace production data from another AppInstance and add no run history or step snapshots; release-layout adoption still preserves existing production content and local runtime tuning.
- Existing binary Node access, pinned Gateway SSH identity, fixed typed infrastructure argv, secret and command redaction, protected input cleanup, independent latest-65,536-byte stdout/stderr capture with observable truncation, atomic symlink ownership checks, AppInstance mutation serialization, exact release-layout conversion, removal retention, Route ownership, and deterministic cache failures remain in force.
- Development sources, legacy Instance and Workspace behavior, production provisioning and cloning checkpoints, deployment configuration validation and storage, other AppInstances, existing releases, environment and database bytes, application Processes, and the E2E harness remain unchanged except where an explicitly configured application command changes its own workload.
