# Feature plan

Plan format: 1
Issue: ORB-217
Flow: discovery
Review verdict: PASS

## Outcome

An operator can explicitly and safely convert one existing production AppInstance from a flat checkout and shared PHP runtime to a retained release selected by `current` and an isolated PHP service without losing source, persistent state, local tuning, or recovery progress.

## Code boundaries

In:
- `apps/gateway/routes/api.php`, `app/Http/Controllers/Api/AppInstanceDeploymentLayoutsController.php`, `app/Http/Requests/AppInstances/PrepareAppInstanceDeploymentLayoutRequest.php`, `app/Data/AppInstances/PrepareAppInstanceDeploymentLayoutData.php`, `app/Actions/AppInstances/AdoptProductionLayoutAction.php`, and `tests/Feature/Api/AppInstanceDeploymentLayoutTest.php`: add the authorized `POST /instances/{instance}/deployment-layout` boundary, accept only optional `sqlite_source_path`, return the current AppInstance only after conversion completes, and preserve bounded correlated failures.
- New conversion state under `apps/gateway/app/Domain/AppInstances/DeploymentLayout/**`, `app/Models/AppInstanceDeploymentLayout.php`, a matching explicit migration under `apps/gateway/database/migrations/`, and focused `tests/Feature/Domain/AdoptProductionLayoutTest.php` coverage: persist an immutable preflight inventory and ordered file-movement, persistent-state, runtime-publication, Route-projection, and completion checkpoints; serialize retries for one AppInstance; revalidate the recorded placement before each effect; and keep completed requests read-only and idempotent.
- New native conversion adapters under `apps/gateway/app/Infrastructure/AppInstances/**` plus bounded changes to `ProductionReleaseLayout`, `RemoteProductionAppInstanceSourceLifecycle`, `RemoteProductionPhpRuntimeManager`, `NativeProductionRouteProjector`, `AppInstance`, `AppServiceProvider`, and their focused infrastructure tests: inventory the flat checkout, environment ownership, optional SQLite file, effective shared-pool tuning, destination paths, Git identity, and serving associations before mutation; move the existing directory intact into a deterministic retained release; place `.env` and selected SQLite bytes outside releases; seed supported tuning into the dedicated `local.conf`; validate the new effective identity; select the retained release through `current`; and republish only this workload against its dedicated socket without reloading or resetting another service.
- `packages/php-sdk/src/Requests/AppInstances/AppInstanceDeploymentLayoutRequest.php`, `packages/php-sdk/.ai/rules/public-contract.md`, and `packages/php-sdk/tests/Unit/Requests/AppInstances/AppInstanceDeploymentLayoutRequestTest.php`: add the typed POST request, preserve omission versus an explicit SQLite path, reuse the bounded AppInstance response and error envelopes, and keep placement and conversion policy in the Gateway.
- `apps/cli/app/Commands/Instances/PrepareDeploymentCommand.php` and `apps/cli/tests/Feature/Instances/PrepareDeploymentCommandTest.php`: add `orbit instance:prepare-deployment INSTANCE`, optional `--sqlite-source-path`, and `--json`; validate only the local scalar inputs, send one SDK request over HTTP, and render deterministic value-bounded human, JSON, and correlated failure output.
- `apps/gateway/app/Domain/Processes/ProcessAdmissionLock.php`, `app/Actions/Processes/AddProcessAction.php`, `StartProcessAction.php`, `RestartProcessAction.php`, and `tests/Feature/Domain/AppInstanceProcessAdmissionConcurrencyTest.php`: make AppInstance Process add, start, and restart share the same per-AppInstance admission owner; hold that owner from the SQLite active-Process preflight through the persistent SQLite placement checkpoint; and re-resolve Process ownership and conversion state after admission so a queued mutation cannot act on a stale preflight.
- Focused Gateway regression coverage beside the existing release-layout, environment, PHP runtime, Route projection, Process, and removal tests: prove preflight has no remote effects, each checkpoint resumes without replacing retained content, completed retries preserve later edits, SQLite relocation rejects active owned Processes or any open handle, concurrent Process add/start/restart cannot invalidate SQLite quiescence, converted removal uses normal retention, and development, fresh production, Node-owned Processes, other users, legacy Instance, and Workspace behavior stays unchanged.

Out:
- Application database schema conversion stays unchanged; conversion can relocate one selected SQLite file but does not inspect or migrate its schema.
- Production creation and cloning stay unchanged; existing instances acquire no candidate, while the candidate requirement for new production AppInstances remains in force.
- Fleet-wide migration stays unchanged; the endpoint converts only the explicitly addressed AppInstance and adds no batch, startup, or automatic migration path.
- Application commands stay agent-owned; conversion infers no maintenance, shutdown, queue, framework-cache, deployment, migration, or recovery command.
- Legacy `Instance` and `Workspace` models, APIs, commands, source layouts, and runtimes stay unchanged.
- `apps/e2e` and `bin/e2e-*` harness code stay unchanged; discovery uses the prepared topology through existing commands and creates no proof plan or fixture.

## Implementation order

1. Add failing API and coordinator tests for eligibility, authorization, optional SQLite input, complete no-effect preflight, durable checkpoint creation, retry identity, completed idempotency, and bounded errors; add the minimal migration, state model, enums/value objects, and relations needed to make the lifecycle explicit.
2. Implement one serialized preflight that snapshots the active flat production AppInstance, parsed and stored environment configuration, Git/source identity, filesystem destinations, optional SQLite state, shared PHP pool and effective tuning, Route/Caddy/socket associations, and Process/open-file state before recording acceptance or allowing a remote effect. When SQLite relocation is requested, acquire the AppInstance's `ProcessAdmissionLock` before checking active Processes and retain it through the persistent SQLite placement checkpoint.
3. Implement idempotent source and persistent-state effects that move the original checkout directory intact into its recorded retained-release destination, place `.env` and optional SQLite bytes at their production-home destinations, create only authenticated links, update `checkout_path` only at the matching checkpoint, and resume every partial filesystem shape without fetching or replacing retained content. Route AppInstance Process add, start, and restart through the same admission owner and revalidate after lock acquisition; add a concurrency test that pauses conversion after its clean Process snapshot and proves no mutation can become active before SQLite placement completes.
4. Extend dedicated runtime convergence to accept the preflighted supported tuning once, validate generated plus local configuration against the recorded identity, start only the AppInstance's dedicated service, and preserve exact tuning across retries; reject unsupported or identity-changing directives before the source move.
5. Under the existing projection owner, validate the recorded Route and old serving association, select the retained release, republish this workload's Caddy configuration to the dedicated socket, checkpoint the projection, and mark completion only after the database record, `current`, effective runtime, and serving path agree; keep the old shared master untouched.
6. Wire the Gateway request, controller, route, authorization, AppInstance response, provider bindings, activity/redaction boundary, and focused API tests around the coordinator without duplicating domain or remote policy in HTTP code.
7. Add the typed PHP SDK request and update its exhaustive public-contract guidance, then add the thin CLI command and their focused transport, omission, output, request-ID, error, and redaction tests.
8. Acquire discovery after plan approval, execute every named observation, and record its exact evidence in ignored `.loop/development.md`. Run all focused and changed-project checks, commit and push only candidate product, test, and documentation files, run the Builder's root `composer check` on that exact clean commit, then publish `.loop/development.md`, the plan, and other session-independent evidence through the separate candidate-bound artifact ref for independent code review.

## Must preserve

- ADR 0031: conversion keeps the exact existing production source instead of cloning over it, performs no later Git mutation, preserves unrelated content and operator-owned source changes, and leaves converted application content under the normal production-removal retention boundary.
- ADR 0038: normal AppInstance removal still cascades through every owned Process and Schedule, retains resumable cleanup on failure, reports no success while cleanup is incomplete, and leaves other AppInstances, Node-owned schedules, and unrecognized runtime artifacts untouched.
- ADR 0044: Gateway-stored environment values remain encrypted and authoritative; existing file values enter ownership only through explicit import; stored/local disagreement refuses before mutation; conversion neither silently imports, replaces, exposes, nor synchronizes values and runs no application command, cache refresh, or process restart.
- ADR 0045: each converted production Unix user receives one dedicated service, pool, socket, and OPcache instance while installed PHP packages remain shared; the operating agent's compatible local tuning remains Node-owned and separate from generated identity; validation precedes activation; another user's service or OPcache is never reloaded, restarted, or reset.
- ADR 0046: the retained existing checkout becomes the selected release without a fetch; persistent `.env` and optional SQLite stay outside replaceable releases; the effective root remains below `current`; conversion runs no deployment steps or inferred commands; failure remains explicit and recovery stays operator-owned.
- ADR 0047: new production AppInstances still require an eligible clean candidate and prepare source from the App repository; explicit conversion applies only to existing production placements, changes no candidate, source AppInstance, queue, Process, Schedule, or cloning contract, and seeds no unselected database.
- Existing binary Node authorization, request correlation, safe error envelopes, secret and environment-value redaction, AppInstance operation serialization, per-AppInstance Process admission ordering, Route ownership, source/path containment, fixed typed remote argv, and atomic publication/rollback rules remain in force.
- Fresh release-layout production creation, development checkout/worktree placement, legacy Instance and Workspace behavior, other production workloads, and the existing E2E harness remain unchanged.
