## Outcome

An agent can replace an active production preview hostname with an intended private hostname on the same sole Route while Orbit synchronizes the candidate environment, cuts over only after private projections are ready, and retains bounded recovery.

## Code boundaries

In:
- `apps/gateway/app/Actions/Routes/ConvergeRouteAction.php`, `apps/gateway/app/Domain/Routes/RouteHostnameChangeStep.php`, and a new additive migration under `apps/gateway/database/migrations/`: admit an active explicit private production Route with exactly one active target, retain the existing Route and association, add production environment forward and restoration checkpoints without reinterpreting retained development checkpoints, and widen the Route persistence trigger only for this eligible production operation.
- `apps/gateway/app/Actions/AppInstances/SynchronizeAppInstanceEnvironmentAction.php` and the environment contracts under `apps/gateway/app/Domain/AppInstances/Environment/`: reuse the complete stored snapshot, capacity preflight, renderer, and protected writer against a validated candidate or previous Route hostname while an owned transition is in progress; keep the public environment operations' transition refusal unchanged.
- `apps/gateway/app/Infrastructure/AppDev/AppDevSiteRepository.php` and the existing `RouteHostnameProjector` implementation: retain both old and candidate production workload and Router sites across the production environment checkpoint, use the production release root and dedicated PHP socket already represented by the aggregate, publish private DNS last, and normalize or restore only Route-owned Caddy, certificate, firewall, and DNS projections.
- `apps/gateway/tests/Feature/Api/RoutesTest.php`, `apps/gateway/tests/Feature/Domain/ConvergeRouteActionTest.php`, `apps/gateway/tests/Feature/Domain/RouteMutationReconciliationTest.php`, `apps/gateway/tests/Feature/Domain/AppInstanceEnvironmentConcurrencyTest.php`, `apps/gateway/tests/Feature/Domain/AppInstanceEnvironmentRenderingTest.php`, `apps/gateway/tests/Feature/Infrastructure/AppInstances/NativeDevelopmentRouteProjectorTest.php`, and `apps/gateway/tests/Feature/Database/RouteMigrationTest.php`: cover production API admission, candidate environment rendering, projection ordering, schema constraints, all recovery boundaries, operation-owner exclusion, untouched production state, and retained development behavior.

Out:
- Application cache commands, Composer, Artisan, framework bootstrap, service or worker restarts, application health gates, and deployment execution remain separate agent-configured work.
- Public exposure, Ingress, public certificates, public DNS, and Route publication-intent changes remain unchanged.
- Additional aliases, new Route records, target changes, multi-target hostname changes, and load-balancing policy remain unchanged.
- Deployment branch, source, retained releases, `current`, SQLite data, AppInstance identity or placement, production runtime identity, and local PHP or PHP-FPM tuning remain unchanged.
- Generated hostname reconciliation and automatic hostname changes from Node or Cluster TLD edits remain behind the existing reconciliation guard.
- PHP SDK and CLI Route transport remain unchanged because they already use the existing `PATCH /routes/{route}` contract and expose the durable Route fields.
- The Incus harness under `apps/e2e` and `bin/e2e-*` remains unchanged; discovery uses the prepared topology and existing guest command surface.

## Incus observations

- Incus: required. Flow: discovery. After independent plan approval, use the prepared ORB-201 discovery topology with a production AppInstance created from a candidate and its active explicit private preview Route. No proof topology, proof plan, immutable evidence capture, or observed-input instrumentation is required in discovery flow.
- Run `production-preview-hostname` against both a standalone production workload and, when the prepared topology permits it, a Cluster-scoped workload behind a separate Router. Record the Route and target IDs, request an invalid hostname and a hostname owned by another Route, and confirm no stored or remote change. Then patch the preview to an available private hostname and confirm the response and Gateway records keep the same Route ID, one target row, active AppInstance, private publication, and Node-or-Cluster scope while old DNS and TLS no longer serve.
- Run `production-preview-env-sync` after storing an `APP_URL` that uses the supported AppInstance-hostname placeholder, a literal `APP_KEY`, an unrelated literal, and another supported placeholder. Capture the old protected production-home `.env`, complete the hostname patch, and inspect that the rendered `APP_URL` and hostname references use the candidate while the stored rows, literal key, unrelated value, production release link, workload Caddy site, Router site when present, certificate scopes, firewall policy, and private DNS agree with the new hostname. Confirm the old Route-owned projections are cleaned only after the new intent is active.
- Run `production-preview-cached-config` with a deployed Laravel release whose cached `app.url` still names the preview and whose request returns HTTP 500. Record the selected release, PHP-FPM service PID, cached configuration bytes, worker state, and deployment output before the patch. Confirm the Route transition succeeds, changes only the protected `.env` and Route-owned infrastructure, and leaves the cache bytes, service PID, release selection, and worker state unchanged; no application HTTP success is required.
- Run `production-preview-retry` by causing one candidate projection failure before private DNS publication, then restore the prerequisite and repeat the same patch. Confirm the old Route, `.env`, and reachable projections remain authoritative after the failed attempt and the retry completes without a second Route or target. Repeat with a restoration interruption and a post-cutover cleanup interruption: the Route must expose its exact checkpoint and failure, a different requested hostname must refuse, and the identical retry must finish restoration or cleanup from current evidence without claiming completion early.
- During a retained `production-preview-retry` boundary, attempt one deployment, a clone that uses the production AppInstance as its candidate, removal, and a stored environment update as applicable to the topology. Confirm each competitor waits or returns the bounded owner conflict before mutation. Compare the source commit and dirty state, selected `current` target, SQLite digest, production runtime identity, and local tuning bytes before and after the completed hostname transition.
- Finish discovery with `bin/e2e-topology sync ORB-201` and `bin/e2e-topology verify ORB-201`. Record `Discovery development only; isolated acceptance proof not run` in the implementation handoff.

## Implementation order

1. Extend the Route migration tests and add a new migration that admits exactly one active production target during a hostname operation, adds production environment checkpoint values, preserves current development state values, and refuses downgrade while production recovery remains unfinished.
2. Add a validated route-transition mode to the environment context, store, and synchronizer so production can preflight, snapshot, render, write, and revalidate the candidate or previous hostname without weakening the public endpoints' refusal or exposing values.
3. Extend `ConvergeRouteAction` eligibility and checkpoint selection by environment: keep the existing development Laravel configuration path, use complete stored-environment synchronization for production, restore the previous environment before rollback completes, and revalidate the candidate environment before post-cutover cleanup retry.
4. Teach aggregate site selection to retain the candidate production workload and Router sites at the production environment checkpoint, then exercise the existing certificate, Caddy, firewall, workload verification, and DNS-last projector on the production release root and dedicated PHP socket.
5. Add focused API, state-machine, rendering, concurrency, persistence, and infrastructure coverage for preview replacement, stored literal preservation, no application command or cache effects, every failure boundary, owner conflicts, untouched production state, and unchanged development hostname convergence.
6. Run Gateway TIA and project checks, complete the four reproducible Incus discovery observations, synchronize and verify the topology record, and retain the exact clean candidate for the Builder gate.

## Must preserve

- ADR 0009: keep the Route as the hostname and publication owner, keep its target derived from the same AppInstance and Node, preserve separate workload and Router keys and original-hostname Host/TLS identity, use LAN before WireGuard, publish DNS last, and add no multi-target selection policy.
- ADR 0023: use the explicitly supplied hostname, keep scope independent from hostname text, project the same hostname to the workload and required Router, keep workloads private, reconcile before the new hostname becomes authoritative, and do not turn Node TLD edits into automatic explicit-hostname changes.
- ADR 0028: the active AppInstance remains targeted by exactly one Route; replacement neither creates another Route nor clears or replaces its target.
- ADR 0029: derive the canonical Laravel URL from the sole Route, make application configuration and Route intent consistent or restore them together, and preserve unrelated application settings.
- ADR 0030: retain runtime, network, TLS, and firewall validation while requiring no Composer, Artisan, dependencies, framework boot, application health check, successful HTTP response, application key, or database.
- ADR 0044: keep stored environment configuration authoritative and encrypted, resolve references against the destination AppInstance, preflight access and placement before decryption, atomically install the complete file, preserve stored literals, import no local edits, disclose no values, and run no application command, cache refresh, or process restart.
- ADR 0045: keep the production user's dedicated PHP-FPM service, pool, socket, OPcache, generated identity, and local tuning unchanged; hostname replacement does not refresh or reload any runtime.
- ADR 0046: keep persistent environment and optional SQLite data outside releases, require a separate explicit deployment, insert no application command, leave `current` and retained releases unchanged, and leave application compatibility and recovery commands with the operating agent.
- ADR 0047: retain the candidate clone's sole explicit private preview Route, require explicit replacement, keep cloning and deployment separate, and preserve source, stored configuration, SQLite data, stopped Process/Schedule state, generated caches, dependencies, and local tuning outside the Route operation.
- Existing invalid/occupied hostname refusal, development hostname convergence, generated and multi-target reconciliation guards, publication and target guards, response redaction, Node access, AppInstance removal, clone, deployment, environment, and private Router tests remain green.
