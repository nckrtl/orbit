# Feature plan

Issue: ORB-127
Review verdict: FIX

## Outcome

Create a development AppInstance as one resumable operation that selects any compatible PHP runtime from its source, provisions its sole private Route, aligns Laravel configuration when detected, and returns the active HTTPS endpoint through Gateway, SDK, and CLI without an application health gate.

## Review findings

- `FIX` — Acceptance items 7, 10, and 11 require a dedicated Router-only Node to have the Caddy, certificate, service, failure, and recovery prerequisites for a working Cluster-scoped Route. The plan adds `RouterRoleBaseline` to the baseline converger and catalogs, but it does not connect that baseline to the protected Router lifecycle. The current `SetClusterRouterAction` directly creates an active Router assignment without `RoleBaselineConverger`, generic `AddNodeRoleAction` rejects Router, and replacement and `ClearClusterRouterAction` delete Router assignments without baseline cleanup. Add the exact Router set, replace, clear, retry, and recovery boundary: converge before active assignment, retain a recoverable failed state, clean up the old baseline only when the Route guard permits the mutation, and prove those action entry points with focused API tests and the dedicated Router Incus case.
- `FIX` — Acceptance items 2 and 3 and ADR 0034 require deterministic selection of the highest Orbit-supported compatible PHP version, but the plan's “pinned Sury runtime candidate catalog” has no exact source or current candidate set. Current `SupportedPhpVersion` accepts every canonical version at or above 8.4, so it cannot supply a finite ordered set, while the existing package manager validates versions only after another boundary requests them. Name one code-owned candidate source, its current ordered members, and the outcome when a candidate is unavailable from the pinned Sury source; bind source constraints above, below, and between those candidates to focused tests and document the supported selection limit in `docs/reference/php-runtime.md`.
- `FIX` — Acceptance item 13 and the `writing-documentation` rule “keep one mechanism in one place” require one owner for Composer-driven selection. `docs/domains/applications.md` repeats the PHP-project predicate, compatible-version choice, PHP 8.5 default, non-PHP result, invalid/unsupported refusal, and AppInstance-field exclusions already owned by `docs/reference/php-runtime.md`. Keep the provisioning-flow context and link in the domain guide, and keep the selection mechanism and limits in the PHP runtime reference.
