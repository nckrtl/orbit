# Feature plan

Issue: ORB-127
Review verdict: BLOCK

## Outcome

Create a development AppInstance as one resumable operation that returns its active sole Route and Laravel-aware HTTPS URL after Orbit prepares the source and initial private Node or Cluster traffic path without treating application health as a provisioning gate.

## Code boundaries

In:

- `apps/gateway/database/migrations/*app_instance_route*`, `apps/gateway/app/Models/{AppInstance,Route,RouteTarget}.php`, and `apps/gateway/app/Domain/{AppInstances,Routes}/**`: add the upgrade preflight and database constraints for at most one Route per AppInstance and exactly one Route per active AppInstance. The migration inspects all legacy associations before its first schema write, reports every invalid active AppInstance, preserves valid rows, replaces the old pending-only Route lifecycle constraints, and adds durable provisioning-step and failure evidence used by retries.
- `apps/gateway/app/Actions/AppInstances/{CreateAppInstanceAction,RemoveAppInstanceAction}.php`, `apps/gateway/app/Actions/Routes/**`, `apps/gateway/app/Data/AppInstances/AppInstanceData.php`, `apps/gateway/app/Http/Controllers/Api/AppInstancesController.php`, and `apps/gateway/app/Domain/AppInstances/**`: preflight hostname generation before source or runtime mutation, keep the current managed-clone source transitions, associate one pending Route before activation, resume each recorded provisioning boundary, activate the AppInstance and Route together, return the Route and hostname, report bounded failure steps, and refuse active removal before source deletion or Route detachment.
- `apps/gateway/app/Domain/AppInstances/*Laravel*` and `apps/gateway/app/Infrastructure/AppInstances/*Laravel*`: detect Laravel from source without Composer, Artisan, vendor code, or application bootstrap; atomically set `APP_URL=https://<hostname>` in an existing environment file or a copied template; update a stale cached `app.url`; preserve unrelated bytes and settings; and reject symlinked, malformed, unsafe, or unverifiable configuration before publication. `apps/gateway/tests/Feature/Infrastructure/AppInstances/LaravelUrlConfigurationTest.php` owns the focused file-shape, preservation, idempotency, and failure proof.
- `apps/gateway/app/Domain/Routes/**`, `apps/gateway/app/Infrastructure/Routes/**`, `apps/gateway/app/Infrastructure/AppDev/{AppDevCaddyConfigRenderer,AppDevCaddyPublisher,AppDevDnsConfigRenderer,AppDevSiteRepository,DnsmasqPrivateDnsManager,RemoteAppDevPhpFpmManager}.php`, `apps/gateway/app/Infrastructure/Firewall/NodeFirewallRuleCatalog.php`, and `apps/gateway/app/Providers/AppServiceProvider.php`: add the initial private Route provisioner and typed projection state. It prepares the workload PHP-FPM pool, separately keyed workload and Router certificates, one composed Caddy service per Node, exact private firewall access, and Gateway DNS last. Node scope serves the configured document root on the workload Node. Cluster scope sends the original Host and TLS server name through the Router, selects configured LAN without fallback and otherwise WireGuard, and uses the local runtime instead of self-proxying when roles co-locate.
- `apps/gateway/app/Domain/Routes/*Reconciliation*`, `apps/gateway/app/Actions/Routes/{UpdateRouteAction,SetRouteTargetAction,ClearRouteTargetAction,RemoveRouteAction}.php`, `apps/gateway/app/Actions/Clusters/{AttachClusterNodeAction,DetachClusterNodeAction,SetClusterRouterAction,ClearClusterRouterAction,UpdateClusterAction}.php`, and `apps/gateway/app/Actions/Nodes/ProvisionNodeAction.php`: return `route.reconciliation_required` before any active Route, source, configuration, Node, Cluster, Router, or projection mutation that would change the serving hostname, target, naming basis, routing scope, or removal state. Identical no-change requests and mutations that affect no active Route retain their existing behavior.
- `apps/gateway/tests/Feature/Api/{AppInstancesTest,RoutesTest}.php`, `apps/gateway/tests/Feature/Database/AppInstanceRouteConstraintTest.php`, `apps/gateway/tests/Feature/Domain/{ProvisionDevelopmentAppInstanceTest,RouteMutationReconciliationTest}.php`, and focused tests under `apps/gateway/tests/Feature/Infrastructure/{AppInstances,Routes}/**`: prove API shape, constraint races and upgrade refusal, ordered step resume, Laravel preservation, topology selection, renderers, certificates, firewall policy, publication ordering, failures, and mutation guards with existing source and legacy records unchanged.
- `packages/php-sdk/src/Responses/AppInstances/{AppInstanceResponse,AppInstanceRouteResponse,AppInstancesResponse}.php` and `packages/php-sdk/tests/Unit/Requests/Instances/InstanceRequestsTest.php`: map the bounded nested sole Route and derived hostname in create, list, show, and remove responses while retaining the existing four AppInstance request operations, omission rules, request ID, redaction, and framework-neutral transport.
- `apps/cli/app/Commands/Instances/{CreateInstanceCommand,ListInstancesCommand,ShowInstanceCommand,RemoveInstanceCommand}.php` and `apps/cli/tests/Feature/Instances/InstanceCommandsTest.php`: render the Route identity, hostname, and `https://` URL in deterministic human and JSON AppInstance output without adding commands or making local routing, Laravel, infrastructure, or health decisions.

Out:

- `apps/gateway` App identity and source-layout migrations remain unchanged: no stable default-instance identity, existing-source registration, production placement, or App source-setting update is added.
- Existing active Route changes and removal remain guarded rather than reconciled: no traffic cutover for retargeting, renaming, scope changes, or removal; no public Ingress or public DNS provider; and no multi-target balancing policy is implemented.
- `apps/gateway` App setup-step configuration and execution, inferred dependency installation, application health state, and operator deployment commands remain unchanged. Laravel detection only owns canonical URL files.
- `apps/e2e/**` and `bin/e2e-*` remain unchanged. Incus coverage is expressed only through `.loop/proof/ORB-127.json` and optional sibling fixtures during implementation.
- Legacy `Instance` and `Workspace` records, source, hostnames, certificate fields, runtime, API identity, and conversion behavior remain unchanged except that shared Caddy, DNS, PHP-FPM, and firewall publishers must continue to compose their existing projections with new AppInstance projections.
- Dependency manifests, unrelated components, GitHub, Linear, the discovery topology, proof topology promotion, and production release remain unchanged by implementation.

## Review findings

- `BLOCK — ISSUE_CREATION_DEFECT` — Scope requires workload runtime preparation, and Acceptance items 4, 8, and 13 require a Laravel clone to reach PHP-FPM and make runtime failures resumable, but ORB-127 does not define the PHP version for a development AppInstance. ADR 0021 defines installation and pool behavior for each concrete version, while the current `AppInstance` model, API, SDK, and CLI have no PHP-version field or input and `AppDevSite` requires one. The plan's instruction to “extend PHP-FPM site publication” therefore leaves the implementer to choose a hard-coded default, infer from source, inherit from another record or Node setting, or add persisted identity. Those choices change runtime ownership and upgrade behavior. The smallest safe resolution is to return ORB-127 to Backlog and amend its contract with one authoritative PHP-version source, its persistence and response behavior, and missing or unsupported-version outcomes and proofs. This is a product and runtime-ownership decision for the repository owner; the plan reviewer cannot choose it.
- `BLOCK — ISSUE_CREATION_DEFECT` — Acceptance items 5 through 7 distinguish Laravel from non-Laravel source, and ADR 0030 requires URL alignment for a “detected Laravel” application, but neither source defines the positive detection evidence or the outcome for partial, conflicting, malformed, or unsafe evidence. The plan invents “detect Laravel from source” plus several refusal cases without a closed predicate. Different plausible predicates, such as `composer.json`, `artisan`, bootstrap files, or a combination, decide whether Orbit mutates `.env` and cached configuration or skips required URL alignment. The smallest safe resolution is to define the exact filesystem evidence, safe-file rules, and fail-versus-no-op result for every ambiguous case in ORB-127, then bind those cases to `LaravelUrlConfigurationTest.php` and the Laravel/non-Laravel Incus actions. This source-mutation boundary belongs to the repository owner.
- `BLOCK — ISSUE_CREATION_DEFECT` — Scope requires initial private firewall projection, and Acceptance item 12 requires “authorized private requests” while refusing unintended public workload access, but ORB-127 and ADR 0009 do not close the source/interface policy. ADR 0009 says workload Nodes allow required HTTPS over WireGuard and configured LAN paths, including authorized Router ingress, but it does not say whether Node-scoped clients include every WireGuard peer, only the Gateway, selected peers, or another set, nor which LAN sources are authorized. The plan's “exact private firewall access” would make the implementer invent a security boundary. The smallest safe resolution is to add an explicit source, destination, port, and ingress-interface matrix for Node scope, Cluster Router ingress, LAN, WireGuard, and co-located roles, with positive and negative firewall proof. This network authorization decision belongs to the repository owner and, if it changes the durable role boundary, an accepted ADR.
- These three gaps existed when ORB-127 was published directly into claimable `Todo` at 2026-09-05T10:16:55Z and moved to `In Progress` at 2026-09-05T10:24:56Z. ADRs 0009, 0021, 0029, and 0030 were already accepted on the branch base, all three `blocked by` issues are complete, and Linear has no later activity that supplies the missing decisions. The classification is therefore `ISSUE_CREATION_DEFECT`, not `POST_CREATION_DRIFT` or `PREFLIGHT_BLOCKER`.
- `FIX` — Acceptance item 17 and the reviewing-feature-plans documentation-audit rule require every discovered drift item to be fixed or reported with an owner. The recorded audit includes `docs/reference/apps.md`, but the page still tells readers to use a separate App update operation while the current Gateway, SDK, and CLI expose only list, show, create, and remove; ORB-101 owns that future update behavior. Change `Reported: none` to report this drift and owner, or correct the page if the owning contract authorizes that correction.
- `FIX` — Acceptance item 17 and `writing-documentation` require one mechanism in one place and one-line Markdown paragraphs. The changed `docs/architecture.md` repeats the managed-clone state transitions, branch selection, retry, Laravel, runtime, and Route-provisioning mechanism owned by `docs/domains/applications.md` and `docs/reference/routes.md`; route the core page to those owners instead. Several changed pages also retain hard-wrapped prose paragraphs. Normalize every changed page even though `composer docs-lint` currently exits `0`; lint does not close these writing rules.
- `FIX` — Acceptance items 9 and 12 permit a dedicated Cluster Router and require its Caddy listener and firewall path, but the plan neither names the Router-role prerequisite boundary nor proves a Router-only Node. Current `NativeRoleBaselineConverger` explicitly gives Router no host baseline, while Caddy and OpenSSL prerequisites come from other role baselines. Add the exact Router prerequisite and lifecycle boundary, focused tests, and a dedicated Router-only Incus case so co-location cannot hide the missing packages or service ownership.
- `FIX` — Scope requires guards against every mutation that invalidates an active Route, and Acceptance item 14 names Route, Node, and Cluster naming or scope changes. The plan names several actions but does not explicitly cover or prove active Route publication-intent changes or workload and Router address changes through `wireguard_ip` and `lan_ip`. Add a closed mutation-entry-point matrix and focused cases for those fields, including identical no-change requests, so an address or projection change cannot bypass `route.reconciliation_required`.
- `FIX` — Acceptance items 5, 6, 11, and 13 put environment values, cached configuration, certificates, and private keys through remote infrastructure operations. The Gateway infrastructure rule requires secret bytes to stay out of local and remote argv, `ProcessInvocation` state, exception or debug text, API responses, and activity data. Add that invariant to the Laravel and certificate boundaries and prove stdin or mode-0600 file transport plus redaction for success, failure, and retry.
