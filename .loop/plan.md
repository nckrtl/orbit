## Outcome

## Must preserve

- ADR 0025: one App owns `default_branch`; `default` is reserved; only it gets the unprefixed generated hostname; every other name is the prefix; identity, placement, and Route survive branch change; named fallback uses the default branch; migration retains Route identity and never overwrites occupied identity or placement. Future default-branch update must reconcile an inherited default source before authority changes and refuse incoherent switching.
- ADR 0027: `instance:new` owns new checkout creation and `instance:register` alone owns adoption. An AppInstance owns one `checkout` or `worktree`; checkout owns its repository, while worktree owns only its directory/admin entry, not common repository or branch. Preserve preflight, resumability, removal ownership/safety, retained local worktree branches, and the ban on remote-branch deletion; do not implement adoption or removal redesign here.
- ADR 0028: at most one Route targets an AppInstance, every active AppInstance has exactly one, association precedes activation, only transitional states may lack it, and mutations cannot strand an active AppInstance. Hostname and URL remain Route projections.
- ADR 0029: Orbit derives detected Laravel URL from the sole Route, aligns it before activation, refuses inconsistency, and preserves unrelated settings on development and production Nodes.
- ADR 0030: provisioning completes automatically after Orbit-owned work without manual activation, framework boot, dependencies, health checks, or successful HTTP response. Preserve source, runtime, network, TLS, firewall validation and keep setup-step behavior out.
- ADR 0032: explicit branch wins, persists intent even when equal to default, refuses absence without fallback, survives App default changes, never changes placement/Route identity, and cannot change through create retry.
- Preserve canonical unique repository identity separate from access URL; locked resumable `reserved -> checkout_prepared -> source_resolved -> active`; immutable placement/source/hostname intent; one pending-to-active Route; local deterministic schema upgrade with no remote work; all foreign keys, uniqueness, Route triggers, failure evidence, redaction, binary access, strict JSON, request IDs, and stable order.
- Preserve Route provenance, publication, generation basis, scope, effective-TLD precedence, Router requirement, projection, reconciliation guards, and explicit hostnames. Preserve legacy Instance/Workspace data and Doctor behavior. Doctor remains verify-only with eight families.
- SDK stays framework-neutral Saloon transport with 68 operations and existing endpoints, bounds, TLS, omission, error, request-ID, and redaction behavior. CLI stays stateless and HTTP-only. Product work leaves dependencies, E2E harness, unrelated proof files/components, Linear, GitHub, and release state unchanged.
