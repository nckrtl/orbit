# Feature plan

Issue: ORB-77
Review verdict: PENDING

## Outcome

Add App-owned Routes whose explicit or target-generated hostname, stored generation basis, Node-or-active-Cluster scope, publication intent, lifecycle, and ordered AppInstance targets stay consistent through creation, target changes, and related Node or Cluster mutations without projecting traffic or changing legacy records.

## Code boundaries

In:

- `apps/gateway/database/migrations/*routes*`, `apps/gateway/app/Models/{App,AppInstance,Cluster,Node,Route,RouteTarget}.php`, and `apps/gateway/app/Domain/Routes/**`: add Route and ordered RouteTarget persistence. A Route has restrictive App ownership, one globally unique normalized hostname, immutable `generated` or `explicit` provenance, exactly one mutable nullable-foreign-key XOR Node-or-Cluster scope, a nullable generation-basis Node, typed publication intent, Route-specific `pending` status, and nullable `failed_step` and `error_code`. A generated Route requires its current or retained basis Node; an explicit Route stores no basis. Route targets have a non-negative position unique within the Route, permit several rows for explicit Routes, prevent duplicate AppInstances and duplicate target Nodes within one Route, and cascade only with their Route or referenced AppInstance. Persistence and domain invariants limit a generated Route to one target while public v1 configures at most one target for either provenance.
- `apps/gateway/app/Data/Routes/**`, `apps/gateway/app/Actions/Routes/**`, and `apps/gateway/tests/Feature/{Database/RouteMigrationTest.php,Api/RoutesTest.php}`: add typed explicit create, stable list/show, hostname or publication update, target set/clear, and Route-only removal. Explicit create accepts an optional active app-dev AppInstance target: with a target it derives Node-or-active-Cluster scope and stores no basis; without one it requires exactly one caller-supplied scope. Every explicit creation sets `status = pending`, `failed_step = null`, and `error_code = null`. Generic update can change mutable publication intent or an explicit hostname but cannot change App, scope, provenance, generation basis, lifecycle, failure metadata, or targets. Every ORB-77 mutation that retains a Route preserves the exact lifecycle and failure values; no action advances lifecycle. Identical normalized creation retries return one Route; conflicting identity or intent and every invalid proposal preserve the complete Route.
- `apps/gateway/app/Data/AppInstances/CreateAppInstanceData.php`, `apps/gateway/app/Http/Requests/AppInstances/StoreAppInstanceRequest.php`, `apps/gateway/app/Actions/AppInstances/CreateAppInstanceAction.php`, and `apps/gateway/tests/Feature/Api/AppInstancesTest.php`: accept one optional hostname and preserve the existing managed-clone state machine. Only after the app-dev AppInstance becomes active, create an explicit Route when the hostname was supplied or a generated Route otherwise. Each generated or explicit Route starts with `status = pending`, `failed_step = null`, and `error_code = null`. A generated Route stores the target Node as its basis, derives the hostname from the AppInstance name, App name, and Node-first effective TLD, and derives scope independently from active Cluster membership. Keep source evidence unchanged on Route failure and make an identical active-AppInstance retry complete the same Route exactly once.
- `apps/gateway/app/Domain/Routes/**`, `apps/gateway/app/Actions/Routes/{SetRouteTarget,ClearRouteTarget}Action.php`, and `apps/gateway/tests/Feature/Api/RoutesTest.php`: add one locked proposed-Route reconciler for target changes. Replacing a generated target atomically changes the target row, basis Node, Node-first generated hostname, and Node-or-active-Cluster scope from the new active same-App AppInstance; replacing an explicit target atomically changes only the target and derived scope and preserves its hostname and null basis. Validate the effective TLD, unique hostname, target ownership and activity, resulting scope, and required Router before the write. A failure leaves every Route field and target row unchanged. Clearing or removing the target deletes only that row and retains hostname, scope, provenance, publication intent, lifecycle, failure metadata, and the last generated basis; the old basis remains protected until a later replacement commits its new basis.
- `apps/gateway/app/Domain/Routes/**`, `apps/gateway/app/Actions/Nodes/ProvisionNodeAction.php`, `apps/gateway/app/Actions/Clusters/{UpdateCluster,AttachClusterNode,DetachClusterNode}Action.php`, and `apps/gateway/tests/Feature/Domain/RouteMutationReconciliationTest.php`: reconcile every affected Route under locks before a Node or Cluster TLD, Cluster state, membership, attach, or detach change becomes authoritative. Recompute a generated hostname when the effective TLD of its current or retained basis Node changes. Recompute scope from the current target Node, or from a retained generated basis when no target exists; preserve explicit hostnames and refuse a mutation that cannot derive a valid zero-target explicit scope. Active membership selects Cluster scope even for a TLD-less Cluster, and every Route-owning Cluster requires exactly one active Router. Validate the complete proposed target, basis, hostname, scope, and Router set, then commit the infrastructure and Route state atomically or retain every old Route, Node, Cluster, and membership value.
- `apps/gateway/app/Domain/Routes/RouteRemovalGuard.php`, `apps/gateway/app/Actions/Apps/RemoveAppAction.php`, `apps/gateway/app/Actions/Nodes/{RemoveNode,RemoveNodeRole}Action.php`, `apps/gateway/app/Actions/Clusters/{RemoveCluster,ClearClusterRouter}Action.php`, `apps/gateway/app/Actions/AppInstances/RemoveAppInstanceAction.php`, and `apps/gateway/tests/Feature/Domain/RouteRemovalGuardTest.php`: refuse App removal while it owns Routes, Cluster removal or Router clearing while it scopes Routes, Node removal while it is a direct scope, target host, or current or retained generation basis, and app-dev or app-prod role removal while its Node hosts a target. Run guards before force, purge, offline, remote, or destructive work. After existing AppInstance source removal succeeds, clear only its target rows through the same zero-target retention boundary. Route removal deletes only its RouteTarget rows and Route.
- `apps/gateway/app/Http/Controllers/Api/RoutesController.php`, `apps/gateway/app/Http/Requests/Routes/**`, `apps/gateway/routes/api.php`, `apps/gateway/app/Http/Authorization/{ServingNode,ServingNodeResolver}.php`, `apps/gateway/app/Infrastructure/Activity/CommandActivityTargetResolver.php`, and `apps/gateway/tests/Feature/{Api/RoutesTest.php,Configuration/NodeAccessRouteScopeTest.php}`: expose authenticated `route:list`, `route:new`, `route:show`, `route:update`, `route:target:set`, `route:target:clear`, and `route:remove`. Create accepts App, hostname, publication intent, an optional scalar AppInstance target, and exactly one Node-or-Cluster scope only when the target is absent; update accepts hostname or publication intent; target set accepts one scalar AppInstance. Reject caller-supplied provenance, generation basis, lifecycle, failure, backend Node, address, URL, balancing data, and target arrays. Keep strict top-level JSON, numeric Route binding, thin controllers, stable request IDs, bounded activity subjects, and binary direct-scope or Cluster-member access; list only accessible Routes in stable order.
- `apps/gateway/app/Data/Instances/InstanceData.php` and `apps/gateway/app/Data/Workspaces/WorkspaceData.php` remain production-code unchanged; `apps/gateway/tests/Feature/Api/{Routes,Workspaces}Test.php` proves that Route creation, update, target reconciliation, infrastructure reconciliation, clear, and removal do not rewrite legacy Instance `hostname` or `certificate_mode` or Workspace `hostname` fields.

Extend the closed SDK contract from 61 to 68 operations. Preserve caller values and omission rules, but leave hostname, basis, relationship, lifecycle, scope, and target policy to the Gateway. Prove exact methods, endpoints, bodies, bounded DTOs, standard errors, request correlation, hostname inclusion and omission, and the absence of backend or balancing escape hatches.
- `apps/cli/app/Commands/Routes/**`, `apps/cli/app/Commands/Instances/CreateInstanceCommand.php`, `apps/cli/tests/Feature/{Routes/RouteCommandsTest.php,CommandSurfaceTest.php,Instances/InstanceCommandsTest.php}`: add the seven HTTP-only Route commands and `instance:new --hostname`, and extend the exact visible vocabulary and signature matrix from 63 to 70 commands. Reject only locally decidable command-shape errors, including non-numeric required IDs, target arrays, an empty update, a missing target and both-or-neither scope options, or a target combined with caller-selected scope. Send hostname grammar, publication policy, resource relationships, generated-basis policy, and target-reconciliation policy to the Gateway. Render deterministic human and JSON forms, including nullable basis and target, without backend or balancing fields and preserve request-ID errors.

Out:

- Keep Gateway DNS, Transport Layer Security, certificates, Router and workload Caddy rendering, firewall mutation, health, request-path forwarding, Route activation, populated failure metadata, and every other traffic projection unchanged. ORB-78 owns convergence-driven activation, every later lifecycle transition, and populated failure metadata after this stored desired-state boundary.

Do not add target arrays, balancing, weighting, health selection, failover, draining, scheduling, movement, or rebalancing; ORB-84 owns multi-target production routing after another accepted generation-basis decision if generated Routes are included.

Preserve ADR 0009's staged conversion and verified cutover; do not change `apps/e2e`, `bin/e2e-*`, proof files, or harness behavior.

## Must preserve

- ADR 0024, generated identity: derive each generated hostname from the current target AppInstance name, App name, and target Node effective TLD; store that Node as generation basis rather than inferring it from hostname text.
- ADR 0024, target replacement: atomically replace target, basis, hostname, and scope for a generated Route; atomically replace only target and scope for an explicit Route and preserve its hostname and null basis; failed proposals preserve the complete old Route.
- ADR 0024, zero-target ownership: a generated Route retains its last basis Node, hostname, and scope when its target clears; Node removal remains refused while that basis is retained; a replacement releases the old basis only with the atomic commit.
- ADR 0024, generated target limit: never assign more than one target to a generated Route without another accepted generation-basis decision, while retaining ordered one-to-many persistence for explicit Routes and the public one-target limit.
