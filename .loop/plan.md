# Feature plan

Issue: ORB-105
Review verdict: BLOCK

## Outcome

Register a verified caller-local linked Git worktree as a served `registered_worktree` AppInstance and generated Route, while keeping the source externally owned and making unregister remove only Orbit-owned state.

## Must preserve

- ADR 0018 source ownership: `managed_clone` and `registered_worktree` remain immutable, distinct app-dev source kinds; registration never adopts or converts another checkout, and app-prod is not a registered-worktree source kind.
- ADR 0018 caller locality: only the authenticated active WireGuard peer can be the registered Node; caller input cannot select another Node; the Node must be supported, active, and own an active app-dev role.
- ADR 0018 verification: the Gateway independently proves the exact canonical linked worktree, safe ownership and modes, distinct Git and common-directory identity, exact normalized origin, contained effective root, overlap exclusion, and protected-path policy. The verified `.codex` allowance remains narrow and never weakens managed-clone or general protected-path rules.
- ADR 0018 external state: dirty and untracked files, detached HEAD, unpublished commits, later edits, branch creation, commits, and HEAD movement are valid. Stored branch and HEAD are initial observations and never become ongoing source policy.
- ADR 0018 non-ownership: no registration, retry, read, Doctor, guard, or unregister path mutates a source file or runs a Git operation that changes the checkout, index, refs, remotes, worktree inventory, or common Git state.
- ADR 0018 identity and retry: the default name is the directory immediately above the Git top level; names use the existing AppInstance and Domain Name System label grammar without sanitizing or truncating; App, name, caller Node, source kind, canonical checkout, and root override are immutable; identical retries re-verify and resume while conflicts preserve all existing state.
- ADR 0018 serving and access: Orbit serves current effective-root files, grants Caddy and runtime only necessary traversal and site access, records every ACL it adds, and exposes no sibling worktree, checkout-control, common-Git, credential, or Codex-control content.
- ADR 0018 availability and Doctor: missing or invalid external source makes the registration unavailable but does not delete it; Doctor verifies source, ACL, runtime, Route, and health with bounded evidence and remains verify-only; restoration revives the same identity.
- ADR 0018 unregister: remove or disable Orbit-owned Route, runtime, certificate, Caddy, firewall, health, and safely recorded ACL state before deleting the registration; absent source is not a cleanup blocker; never delete or prune the worktree, parents, branches, refs, checkout, or common Git directory; source-kind-specific remove and unregister refusals remain explicit.
- ADR 0023 supersedes ADR 0018 and ADR 0017 wherever their older TLD or scope text conflicts: the Node TLD has generated-hostname priority, the active Cluster TLD is only the fallback when the Node has no TLD, active Cluster membership selects routing scope independently, a Route-owning Cluster has exactly one active Router, and the Route alone owns the hostname.
- ADR 0023 projection path: a Cluster-scoped hostname projects to its Router and target workload Node, private allowed clients may reach the workload projection without changing scope, public traffic is not introduced here, co-located roles keep the same logical path, and an invalid proposed hostname, scope, target, or required role fails before mutation becomes authoritative.
- ADR 0024 generated identity: the registered AppInstance's Node is both current target and generation basis; generated hostname, target, basis, and scope move atomically under later accepted mutations; the Route stays single-target and retains hostname, scope, and basis if its target is ever cleared.
- ADR 0009 ownership and placement where later ADRs leave it in force: an App owns its AppInstances and Routes; an AppInstance belongs to exactly one App and Node and owns its immutable checkout path and effective root; targets reference AppInstances rather than independent Nodes; Node application roles own runtime prerequisites, and AppInstances do not select or install private PHP runtimes.
- ADR 0009 routing safety: the accepted direct or Router workload path, route-scoped certificate separation, original Host and TLS server name, LAN-before-WireGuard application address, firewall ownership, trusted health, deterministic zero-target unavailable response, and single active target policy are not widened or redefined.
- ADR 0017 where ADR 0023 leaves it in force: Cluster membership remains optional, standalone Nodes are supported, membership does not grant or remove roles, Node and Cluster TLD uniqueness remains enforced, and routing mutations stay idempotent, resumable, and fail closed without relabeling source or changing placement.
- ADR 0016 App reconciliation: registered worktrees participate in later repository preflight without Orbit changing their remote; `.env` URL replacement excludes registered source; slug, repository, main-branch, and root reconciliation remain outside ORB-105 and must never move or rewrite registered source.
- Existing AppInstance creation tests keep `reserved -> checkout_prepared -> source_resolved -> active`, exact managed clone and origin verification, immutable branch, commit, root, and checkout evidence, idempotent activation, refusal-first removal, and safe exact-clone cleanup. Registered projection work must not weaken `AppInstanceSourceBoundaryTest.php` or make `instance:new` serve source in this issue.

The smallest safe resolution is to return ORB-105 to `Backlog` through `creating-issues`, retain the dependency, let ORB-78 land, then reconcile and review this plan again. The apparent decision boundary is ORB-78 lifecycle and dependency completion, not a new ORB-105 product decision.
- BLOCK — `ISSUE_CREATION_DEFECT` — Acceptance item 4 requires every registered URL to be `<name>.<app-slug>.<effective-tld>`, but attached ADR 0018's “Derive a stable default identity and development hostname” decision requires ADR 0009's distinct main and feature shapes, and the current Route contract maps an AppInstance whose name equals `App.main_branch` to `<app>.<tld>`. The plan omits this exact hostname-shape branch from its acceptance row and implementation order while declaring no open question, so it cannot preserve both contracts. ORB-105 most recently entered the claimable `In Progress` state on 2026-09-04 at 20:39 UTC, after ADR 0018 and the ADR 0023/0024 Route contract were accepted and present on `main`; the incompatibility therefore existed at the claimable-state baseline.
